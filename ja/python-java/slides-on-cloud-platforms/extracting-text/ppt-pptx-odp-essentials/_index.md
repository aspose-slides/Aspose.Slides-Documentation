## **はじめに**

プレゼンテーションテキストの抽出により、スライドコンテンツを検索、分析、アクセシビリティ、ローカリゼーションで利用できるようになります。Python アプリケーションでは、抽出したテキストをインデックスやドキュメント管理システム、あるいは言語処理パイプラインに供給できます。クラウドワーカーは、アップロードやオブジェクトストレージから受け取ったファイルに対して同じワークフローを適用できます。

この記事では、PPT、PPTX、ODP がテキストをどのように格納しているか、そしてそれらの違いが抽出にどのように影響するかを説明します。Aspose.Slides for Python via Java は 3 つのフォーマットすべての読み込みをサポートしています。詳しくは[Supported File Formats](/slides/ja/python-java/supported-file-formats/)。

## **テキスト抽出の実践的な応用**

- **ドキュメント ワークフロー:** プレゼンテーションコンテンツをドキュメント管理システムにインポートし、ソースファイルのメタデータと関連付けます。
- **検索インデックス作成:** スライドテキストをインデックス化し、結果ごとにプレゼンテーション名とスライド番号を保持します。
- **コンテンツ分析:** プレゼンテーションアーカイブ全体のトピック、用語、再発テーマを特定します。
- **アクセシビリティとローカリゼーション:** 支援ツールや翻訳ワークフロー向けにテキストを提供し、読取順序やコンテキストの追加レビューを行います。
- **レイアウト分析:** スライド構造のチェックや構造化エクスポートの準備時に、テキストとオブジェクト位置を組み合わせます。

## **プレゼンテーションフォーマットの概要**

### **PPT: レガシー PowerPoint フォーマット**

PPT は PowerPoint 97–2003 に対応するバイナリ形式です。そのレコードは XML ドキュメントとして処理できません。パーサーはバイナリ構造とその関係を理解し、スライドコンテンツを再構築する必要があります。

テキストはスライドオブジェクト、ノート、コメントに存在する場合があります。抽出ワークフローは、これらのどのソースを含めるかを定義すべきで、プレゼンテーション全体をひとつの連続テキストとして扱うべきではありません。

### **PPTX: Office Open XML**

PPTX は XML 部分やその他のリソースを含む ZIP パッケージです。スライドテキストは通常、`ppt/slides/ja/slideX.xml` の `a:t` 要素内に出現します。ノートは別個の notes‑slide パーツに保存され、コメントはパッケージのリレーションシップを通じて接続された独自のパーツを持ちます。

スライド XML からテキスト要素だけを読み取ると、パッケージ内の他の場所に保存されたコンテンツを見逃す可能性があります。また、書式や読取順序を再構築しません。完全なワークフローでは、レイアウト、グループ化されたシェイプ、テーブル、チャート、関連パーツを考慮する必要があります。

### **ODP: OpenDocument Presentation**

ODP は LibreOffice Impress などのアプリケーションで使用されるパッケージ化された OpenDocument プレゼンテーション形式です。PPTX と同様に ZIP パッケージ内に XML を含みますが、OpenDocument の語彙と構造を使用します。

プレゼンテーションコンテンツは主に `content.xml` に保存されます。段落テキストは `text:p` などの要素を使用し、スパンやその他のテキスト機能のためにネストされた要素があります。そのため、PPTX 固有の XML クエリは ODP では直接再利用できません。

## **Python で共通のプレゼンテーションモデルを使用する**

The [Presentation](https://reference.aspose.com/slides/ja/python-java/aspose.slides/presentation/) クラスは、サポートされているプレゼンテーションファイルをロードし、アプリケーションコードが各フォーマットごとに個別のパッケージやバイナリパーサーを実装せずにスライドとそのオブジェクトを操作できるようにします。

抽出をクラウドワーカーに統合する前に、[Installation](/slides/ja/python-java/installation/) を参照してください。デプロイや JVM ライフサイクルに関する考慮事項については、[Slides on Cloud Platforms](/slides/ja/python-java/slides-on-cloud-platforms/) をご覧ください。

抽出設計において、これらの決定を明示的に保ってください：

- **コンテンツ範囲:** スライドテキスト、ノート、コメント、テーブル、チャートラベルの取り扱い方法を決定します。
- **読取順序:** スライド境界を保持し、オブジェクト順序が不十分な場合はレイアウト情報を使用します。
- **画像内テキスト:** スクリーンショットやスキャンしたスライドにテキストが埋め込まれている場合は、別個の OCR ワークフローを使用します。
- **出力構造:** ソース識別子を保持し、UTF-8 など必要な言語をサポートするエンコーディングでテキストを書き出します。

## **結論**

PPT はバイナリ形式の処理が必要ですが、PPTX と ODP は異なる XML パッケージ構造を使用します。プレゼンテーションライブラリは、Python でこれらのフォーマットを扱うための共通の出発点を提供します。コンテンツ範囲と読取順序を定義することで、生成されたテキストをインデックス作成、分析、ローカリゼーションに有用にできます。

## **FAQ**

**PPT のテキストをファイルを解凍して抽出できますか？**

いいえ。PPT はバイナリ構造を使用しています。ZIP と XML のアプローチは PPTX や ODP などのパッケージ形式に適用されます。

**PPTX ではノートやコメントはメインのスライドテキストと一緒に保存されていますか？**

それらは別々のパッケージパーツを使用します。スライド XML だけを読み取っても自動的には含まれません。

**プレーンテキスト抽出はスクリーンショット内のテキストを取得できますか？**

いいえ。スクリーンショットのテキストは画像の一部であり、編集可能なスライドテキストではありません。OCR が必要です。
