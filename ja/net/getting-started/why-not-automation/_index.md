## **導入**

Aspose コンポーネントが自動化より優れた代替手段である理由はいくつかあります。主な理由は次のとおりです。

- セキュリティ
- 安定性
- スケーラビリティ/速度
- 価格
- 機能

以下に各ポイントの詳細な説明を示します。

## **重要な質問**

Aspose でよく聞かれる質問が 2 つあります。

- 製品を実行するために Microsoft Office のインストールが必要ですか？

簡潔な回答は **いいえ** です。

Aspose コンポーネントは完全に独立しており、Microsoft Corporation と提携、認可、スポンサー、またはその他の形で承認されているわけではありません。

- なぜ Microsoft Office Automation の代わりに Aspose 製品を使用すべきですか？

まず、[Aspose.Slides を使用すると得られる利点](/slides/ja/net/product-overview/) が多数あります。

次に、Microsoft 自体がソフトウェアソリューションからの Office Automation の使用を **強く推奨しない** と明言しています。

## **セキュリティ**
以下は Microsoft の記事からの直接引用です。

> "Office Applications はサーバー側での使用を想定しておらず、分散コンポーネントが直面するセキュリティ問題を考慮していません。Office は受信リクエストを認証せず、マクロの意図しない実行や、サーバー側コードからマクロを実行する別のサーバーの起動から保護しません。匿名の Web からサーバーにアップロードされたファイルを開いてはいけません！最後に設定されたセキュリティ設定に基づき、サーバーは管理者またはシステム コンテキストでフル特権でマクロを実行し、ネットワークを危険にさらす可能性があります！さらに、Office は Simple MAPI、WinInet、MSDAIPP などの多数のクライアント側コンポーネントを使用し、処理速度向上のためにクライアント認証情報をキャッシュします。Office がサーバー側で自動化される場合、1 つのインスタンスが複数のクライアントにサービスを提供することがあり、セッションの認証情報がキャッシュされているため、あるクライアントが別のクライアントのキャッシュされた資格情報を使用して、他のユーザーになりすまして付与されていないアクセス権を取得する可能性があります。"

Aspose 製品は非常に **安全** です。Aspose コンポーネントはすべての ASP.NET アプリケーションと同じユーザー コンテキスト（ASPNET ユーザー）で実行されます。したがって、Aspose コンポーネントは **セキュリティ上のリスクをもたらしません**。また、重要なシステム リソースを消費しません。さらに、Aspose コンポーネントがドキュメントを開く際に、マクロは自動的に実行されません。Aspose コンポーネントは、開発者が Office ファイルを作成、操作、保存できるように設計されています。

{{% alert color="info" title="注" %}}
Microsoft Office パッケージに関連するリスクは、Aspose コンポーネントには適用されません。
{{% /alert %}}

## **安定性**
以下は前述の Microsoft 記事からの直接引用です。

> "Office 2000、Office XP、Office 2003 は Microsoft Windows Installer (MSI) テクノロジーを使用して、エンド ユーザーのインストールと自己修復を容易にしています。MSI は「初回使用時インストール」という概念を導入し、機能を実行時に動的にインストールまたは構成できるようにします（システム用、または特定のユーザー用）。サーバー側環境では、これによりパフォーマンスが低下し、インストールの承認や適切なインストール ディスクの提供を求めるダイアログが表示される可能性が高まります。Office はエンド ユーザー製品としての回復力を高めるよう設計されていますが、サーバー側環境での MSI 機能の実装は逆効果です。さらに、Office の一般的な安定性はサーバー側で実行された場合に保証できません。これはこの種の使用を想定して設計・テストされていないためです。ネットワーク サーバー上で Office をサービス コンポーネントとして使用すると、そのマシンの安定性、さらにはネットワーク全体の安定性が低下する可能性があります。サーバー側で Office を自動化する場合は、重要な機能に影響を与えず、必要に応じて再起動できる専用コンピューターにプログラムを分離することを検討してください。"

Aspose コンポーネントは単一の DLL にパッケージ化されているため、機能するために追加の部品をインストールする必要はありません。Aspose コンポーネントは .NET アプリケーションのみで使用され、人間の応答を待つようなコードは含まれていません。

{{% alert color="info" title="注" %}}
Aspose コンポーネントは徹底的にテストされており、非常に安定しています。Aspose コンポーネントは **Bank of America** をはじめ、さまざまな業界の多数の主要組織で使用されています。
{{% /alert %}}

## **スケーラビリティ/速度**
以下は Microsoft 記事からの直接引用です。

> "サーバー側コンポーネントは、複数クライアント向けに最小のオーバーヘッドと高スループットを備えた再入可能かつマルチスレッドの COM コンポーネントである必要があります。Office アプリケーションはほぼすべての点で正反対です。これらは再入不可で STA ベースの Automation サーバーであり、単一クライアント向けにリソース集約的な機能を提供するよう設計されています。サーバー側ソリューションとしてのスケーラビリティは低く、メモリなどの重要要素は構成で変更できない固定上限があります。さらに、メモリ マップド ファイル、グローバル アドインやテンプレート、共有 Automation サーバーなどのグローバル リソースを使用するため、同時に実行できるインスタンス数が制限され、マルチクライアント環境で構成された場合に競合状態が発生する可能性があります。複数の Office アプリケーション インスタンスを同時に実行しようとする開発者は、デッドロックやデータ破損を回避するためにプーリングまたはシリアライズされたアクセスを検討する必要があります。"

Aspose コンポーネントは驚異的なスケーラビリティと極めて高速です。Office アプリケーションは数百〜数千人の同時利用を想定していませんが、Aspose コンポーネントはまさにその用途向けに設計された真の .NET ソリューションです。

{{% alert color="info" title="注" %}}
Aspose コンポーネントのパフォーマンスは、単一サーバー（単一アプリケーションを実行）でも、ロードバランスされた Web フォーム（企業全体のアプリケーションを実行）でも完璧です。
{{% /alert %}}

## **価格**
Microsoft Office Automation を利用するアプリケーションでは、アプリを実行する各マシンに Microsoft Office のコピーを購入する必要があります。アプリケーションがオフィス ファイルを作成または操作する場面は多数ありますが、そのプロセス自体は Microsoft Office を必要としません。

{{% alert color="info" title="注" %}}
Aspose は非常に [コストパフォーマンスの高い](https://purchase.aspose.com/) ロイヤリティフリーの再配布ライセンスを提供しており、ユーザー数に制限なく展開でき、ライセンスの心配が不要です。
{{% /alert %}}

Web ベースのアプリケーションを作成する際、Microsoft Office Automation コンポーネントはサーバー側ソリューション向けに価格設定やライセンスが行われていないことを忘れてはいけません。したがって、Microsoft Office コンポーネントを利用した Web アプリケーションの展開に適したライセンス ソリューションはありません。一方、Aspose はサーバー ベースのアプリケーション向けに非常に [コストパフォーマンスの高い](https://purchase.aspose.com/) ソリューションを提供しています。

## **機能**
Aspose コンポーネントは Office ファイルの管理に必要なすべてと、さらに多くの機能を提供します。開発者が最小限の労力で最大の成果を上げられるようにという理念のもとに設計しました。

{{% alert color="info" title="注" %}}
Office Automation とは異なり、Aspose コンポーネントは多数の強力で時間節約になる機能を提供します。
{{% /alert %}}

たとえば、[Aspose.Cells](https://products.aspose.com/cells/net/) は開発者に **DataTable** や **DataView** から直接 Excel ファイルへデータをインポートする機能を提供します。[Aspose.Words](https://products.aspose.com/words/net/) は、任意の .NET データ オブジェクトから直接 Word（メール マージ）ドキュメントを生成できる同様の機能を提供します。[Aspose ファミリーのすべてのコンポーネント](https://products.aspose.com/total/net/) が独自のユニークで強力な機能セットを備えています。

Aspose コンポーネントを購入する最大の利点は、開発チームへのアクセスが得られることです。たとえば、Office Automation オブジェクトを使用していて特定の機能が必要な場合、その機能が追加される可能性は非常に低いです。しかし、Aspose コンポーネントでは状況は異なります。

{{% alert color="info" title="注" %}}
当社の開発チームは、貴社が必要とする機能は他社でも必要とされている可能性が高いことを理解しています。すべての要望を実装できないことは承知していますが、顧客からのフィードバックに基づき、できるだけ多くの機能を追加できるよう努めています。
{{% /alert %}}

当社のチームは常に柔軟で協力的に支援を提供しており、これが Aspose コンポーネントが現在のように強力に成長した理由です。
