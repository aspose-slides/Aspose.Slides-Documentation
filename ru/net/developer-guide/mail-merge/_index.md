# Слияние почты в презентациях PowerPoint

Aspose.Slides для .NET позволяет автоматически создавать презентации PowerPoint, используя шаблон и источник данных. Слияние почты заполняет заполнители шаблона данными и создает либо одну презентацию с повторяющимися слайдами шаблона для каждого набора данных, либо отдельную презентацию для каждого набора данных.

Эта возможность полезна для создания каталогов продукции, персонализированных презентаций, отчетов, сертификатов, предложений, прайс‑листов и других документов, где структура презентации остается неизменной, а содержание меняется.

## Как работает слияние почты

Слияние почты использует презентацию PowerPoint в качестве шаблона и заменяет заполнители значениями из источника данных.

![Workflow слияния почты](mail-merge-workflow.png)

Заполнитель — это имя поля, заключённое в двойные фигурные скобки, например `{{title}}` или `{{price}}`. Заполнители могут находиться в тексте фигур, ячейках таблиц, сгруппированных фигурах и заметках спикера.

Например, шаблонный слайд может содержать следующий текст:

- `Product: {{title}}`
- `Price: {{price}}`
- `Description: {{description}}`

Когда источник данных содержит следующие значения:

| Поле | Значение |
|---|---|
| title | Laptop X1 |
| price | $999 |
| description | 14‑inch display, 16 GB RAM |

Слияние почты заменяет заполнители на соответствующие значения, получая слайд с реальной информацией о продукте.

Имена полей не чувствительны к регистру, поэтому `{{title}}` и `{{Title}}` относятся к одному и тому же полю.

При замене заполнителей применяются следующие правила:

- Заполнители заменяются на слайдах, включая сгруппированные фигуры и ячейки таблиц, а также в заметках спикера.
- Заполнители на мастер‑слайдах и слайдах‑макетах не заменяются.
- Заполнитель, поле которого отсутствует в наборе данных, остаётся неизменным.
- Пустое значение поля заменяет свой заполнитель пустой строкой.
- Вставленный текст наследует форматирование первого символа заполнителя.
- Значения не должны содержать текст заполнителя, потому что вставленный текст может быть обработан повторно и заменён другим полем.

Исходный шаблон презентации не изменяется во время операции слияния и должен содержать как минимум один слайд.

## Поддерживаемые источники данных

Слияние почты поддерживает два способа подачи данных:

- Программно создавать источник данных с помощью `IMailMergeDataSource`.
- Читать данные из файлов или потоков CSV, XLSX, JSON или XML.

Формат данных определяется по содержимому, а не по расширению файла. Поддерживаются также потоки, не поддерживающие перемотку.

Источник данных должен содержать как минимум один набор данных. Каждый набор представляет одну копию шаблона, заполняемую своими значениями.

Если содержимое данных не может быть распознано как поддерживаемый формат, генерируется `NotSupportedException`. Если формат распознан, но не соответствует требованиям, генерируется `InvalidDataException`. Текст исключения содержит информацию о месте ошибки в данных.

### JSON

Источник данных JSON должен иметь корневой объект с массивом `sets`. Каждый элемент массива представляет набор данных и должен содержать массив `fields`. Каждый элемент поля должен иметь строковые свойства `name` и `value`.

Необязательное свойство `version` должно быть `"1.0"`, а необязательное свойство `type` поля — `"text"`. Имена свойств чувствительны к регистру. Неизвестные свойства игнорируются.

JSON‑данные читаются как UTF-8, либо как UTF-16, если данные начинаются с байтовой метки порядка байтов (BOM).

Следующий пример содержит два набора данных:

```json
{
  "version": "1.0",
  "sets": [
    {
      "fields": [
        { "name": "title", "value": "Laptop X1" },
        { "name": "price", "value": "$999" }
      ]
    },
    {
      "fields": [
        { "name": "title", "value": "Tablet S2" },
        { "name": "price", "value": "$499" }
      ]
    }
  ]
}
```

### XML

Источник данных XML должен иметь корневой элемент `template`, содержащий элемент `sets`. Каждый элемент `set` содержит элементы `field`, а каждый `field` должен включать элементы `name` и `value`.

Пустой элемент `value` трактуется как пустая строка. Имена элементов чувствительны к регистру. Неизвестные элементы и комментарии игнорируются. Кодировка определяется объявлением XML. Определения типа документа (DTD) не допускаются.

```xml
<?xml version="1.0" encoding="utf-8"?>
<template>
  <sets>
    <set>
      <field>
        <name>title</name>
        <value>Laptop X1</value>
      </field>
      <field>
        <name>price</name>
        <value>$999</value>
      </field>
    </set>
    <set>
      <field>
        <name>title</name>
        <value>Tablet S2</value>
      </field>
      <field>
        <name>price</name>
        <value>$499</value>
      </field>
    </set>
  </sets>
</template>
```

### CSV

В CSV в качестве разделителей значений используются точки с запятой.

Первая строка содержит имена полей и заканчивается на первом пустом имени поля. Каждая последующая строка представляет один набор данных. Данные заканчиваются на первой пустой строке.

Применяются следующие правила:

- Отсутствующие значения в конце строки трактуются как пустые строки.
- Значения, выходящие за пределы определённых имён полей, игнорируются.
- Значение, содержащее точку с запятой, кавычку или перевод строки, должно быть заключено в кавычки.
- Кавычки внутри кавычек удваиваются.
- Данные читаются как UTF-8, либо как UTF-16, если они начинаются с BOM.

Пример:

```csv
title;price;description
Laptop X1;$999;"14"" display; 16 GB RAM"
Tablet S2;$499;
```

### XLSX

Данные XLSX читаются с первого листа книги.

Лист следует тем же правилам, что и CSV:

- Первая строка содержит имена полей и заканчивается на первой пустой ячейке.
- Каждая последующая строка представляет один набор данных.
- Данные заканчиваются на первой пустой строке.
- Пустые ячейки трактуются как пустые строки.
- Числовые значения преобразуются в текст с использованием нейтральной культуры.

## Создание единой презентации

Метод `MergeToSinglePresentation` создаёт одну презентацию, содержащую копию слайдов шаблона для каждого набора данных. Каждая копия заполняется соответствующими данными.

Порядок наборов данных определяет порядок групп слайдов в полученной презентации.

### Слияние данных из файла

Следующий пример загружает шаблон и файл данных JSON, создаёт единую презентацию со слайдами для всех наборов данных и сохраняет результат.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, "products.json"))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

Данные также могут быть считаны из потока. Поток читается, начиная с текущей позиции, и не закрывается операцией слияния почты.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xml"))
using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, data))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

### Создание источника данных в коде

Можно построить источник данных программно, используя `MailMergeDataSource` и `MailMergeDataSet`. Добавьте набор данных для каждой записи и задайте его поля с помощью метода `AddText`.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet laptop = source.AddDataSet();
laptop.AddText("title", "Laptop X1");
laptop.AddText("price", "$999");

IMailMergeDataSet tablet = source.AddDataSet();
tablet.AddText("title", "Tablet S2");
tablet.AddText("price", "$499");

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, source))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

В этом примере слайды шаблона повторяются дважды: один раз для ноутбука и один раз для планшета. Заполнители заполняются значениями, определёнными в каждом наборе данных.

## Создание нескольких презентаций

Если требуется отдельная презентация для каждого набора данных, используйте метод `MergeToMultiplePresentations`.

Этот метод последовательно обрабатывает наборы данных, создаёт презентацию из шаблона, заполняет её текущими данными и передаёт полученную презентацию обработчику.

Обработчик вызывается один раз для каждого набора данных в исходном порядке.

### Сохранение каждой презентации

Следующий пример читает данные из CSV‑файла и сохраняет каждую сгенерированную презентацию как отдельный файл.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.csv",
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

Свойство `args.Index` предоставляет нулевой индекс текущего набора данных. В примере он используется для создания последовательных имён файлов, начиная с `product_1.pptx`.

Данные также могут быть считаны из потока:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xlsx"))
using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        data,
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

### Использование значений набора данных для имен файлов

Обработчик получает как сгенерированную презентацию, так и информацию о наборе данных, использованном для её создания. Вы можете использовать значения набора данных для построения осмысленных имён файлов.

Например, следующий код сохраняет каждую презентацию, используя название продукта:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string title = args.DataSet.GetText("title");
            string fileName = title != null
                ? title
                : "product_" + (args.Index + 1);

            presentation.Save(fileName + ".pptx", SaveFormat.Pptx);
        });
}
```

Свойство `DataSet` возвращает набор данных, использованный для заполнения текущей презентации. Метод `GetText` получает значение указанного поля или `null`, если поле отсутствует.

Это позволяет использовать значения данных для именования файлов, организации вывода или выполнения дополнительной обработки в обработчике.

## Обработка сгенерированных презентаций

`MergeToMultiplePresentations` использует делегат `MailMergedPresentationHandler` для обработки каждой сгенерированной презентации.

Обработчик получает два аргумента:

- `presentation` — презентация, созданная из шаблона и заполненная текущим набором данных.
- `args` — информация о сгенерированной презентации, включающая индекс набора данных и сам набор данных.

Сгенерированная презентация принадлежит операции слияния почты и освобождается сразу после возврата обработчика. Поэтому её необходимо сохранить или скопировать требуемые данные внутри обработчика. Не сохраняйте ссылку на неё после возврата обработчика и не вызывайте `Dispose` вручную.

Обработчик выполняется в вызывающем потоке, по одной презентации за раз, в порядке наборов данных. В любой момент в памяти держится только одна сгенерированная презентация, что делает данный подход пригодным для обработки больших источников данных без одновременного хранения всех презентаций в памяти.

Если обработчик генерирует исключение, операция слияния останавливается, а исключение передаётся вызывающему без изменений. Уже обработанные презентации остаются без изменений, а оставшиеся наборы данных не обрабатываются.

Следующий пример сохраняет сгенерированные презентации в отдельный каталог:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

string outputFolder = "output";
Directory.CreateDirectory(outputFolder);

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string path = Path.Combine(
                outputFolder,
                "product_" + (args.Index + 1) + ".pptx");

            presentation.Save(path, SaveFormat.Pptx);
        });
}
```

## Работа с данными слияния почты

Класс `MailMergeDataSource` представляет упорядоченную коллекцию наборов данных. Его можно использовать для создания данных в коде, инспектирования количества наборов данных и доступа к отдельным наборам по индексу.

### Получение количества наборов данных

Свойство `Count` возвращает количество наборов данных в источнике.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine("Presentations to create: " + source.Count);
```

### Доступ к набору данных по индексу

Свойство `Item(int)` предоставляет доступ к набору данных по указанному нулевому индексу.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine(source[1].GetText("title"));
```

В этом примере извлекается заголовок второго набора данных.

### Добавление текстовых полей

Метод `AddText` добавляет именованное текстовое поле в набор данных. Значение поля заменяет все соответствующие заполнители в шаблоне.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet dataSet = source.AddDataSet();
dataSet.AddText("title", "Laptop X1");
dataSet.AddText("subtitle", string.Empty);
```

Пустое значение удаляет соответствующий заполнитель из результирующего текста. Если поле не добавлено в набор данных, заполнитель остаётся без изменений.

### Чтение текстовых полей

Метод `GetText` получает значение поля по имени. Имена полей не чувствительны к регистру.

```csharp
IMailMergeDataSet dataSet = source[0];

string title = dataSet.GetText("title");
string price = dataSet.GetText("price");
```

Если поле не существует или указанное имя поля равно `null`, `GetText` возвращает `null`.

Вы можете использовать его для:

- Заполнения шаблонов презентаций данными из источников.
- Создания единой презентации с повторяющимися слайдами шаблона для нескольких наборов данных.

- Чтения данных из файлов или потоков CSV, XLSX, JSON и XML.
- Построения источников данных непосредственно в коде.
- Последовательной обработки и сохранения сгенерированных презентаций с помощью обработчика.

Комбинируя переиспользуемые шаблоны со структурированными данными, вы можете автоматизировать создание большого количества презентаций, удерживая дизайн шаблона и логику обработки данных раздельно.

## Часто задаваемые вопросы

### Можно ли использовать один и тот же заполнитель несколько раз в шаблоне?

Да. Каждое вхождение заполнителя с соответствующим именем поля заменяется на соответствующее значение из текущего набора данных.

### Являются ли имена полей чувствительными к регистру?

Нет. Имена заполнителей и полей данных не чувствительны к регистру. Например, `{{title}}`, `{{Title}}` и `{{TITLE}}` относятся к одному полю.

### Что происходит, если в наборе данных отсутствует поле?

Если набор данных не содержит поле, на которое ссылается заполнитель, этот заполнитель остаётся без изменений в сгенерированной презентации.

### Что происходит, если поле имеет пустое значение?

Пустое значение поля заменяет заполнитель пустой строкой. Текст заполнителя удаляется, не оставляя ничего на его месте.

### Можно ли сохранить форматирование заполнителя при его замене?

Текст замены наследует форматирование первого символа заполнителя. Примените нужное форматирование к тексту заполнителя в шаблоне до выполнения слияния.

### Заменяет ли слияние почты заполнители на мастер‑слайдах или слайдах‑макетах?

Нет. Слияние почты заменяет заполнители только в поддерживаемом содержимом слайдов презентации, включая фигуры, сгруппированные фигуры, ячейки таблиц и заметки спикера. Заполнители на мастер‑слайдах и макетах не заменяются.

### Модифицируется ли шаблон презентации во время слияния?

Нет. Исходный шаблон не меняется в процессе слияния. Его можно многократно использовать для генерации презентаций из одинаковых или разных источников данных.

### Можно ли создать отдельную презентацию для каждого набора данных?

Да. Используйте `MergeToMultiplePresentations` и сохраняйте каждую сгенерированную презентацию внутри обработчика. Обработчик вызывается последовательно для каждого набора данных.

### Можно ли объединить все наборы данных в одну презентацию?

Да. Используйте `MergeToSinglePresentation`. Он создаёт одну итоговую презентацию, содержащую копию слайдов шаблона для каждого набора данных в порядке их появления в источнике.

### Можно ли использовать источник данных без сохранения его в файл?

Да. Вы можете создать `MailMergeDataSource` в коде, добавить наборы данных и заполнить поля с помощью `AddText`. Это удобно, когда данные уже находятся в вашем приложении.

### Определяет ли слияние почты формат данных по расширению файла?

Нет. Формат данных определяется по содержимому, поэтому поддерживаемый источник данных может иметь любой расширение.

### Можно ли читать данные из потока, не поддерживающего перемотку?

Да. Слияние почты поддерживает потоки без возможности перемотки.

### Что происходит, если источник данных пустой или не содержит наборов данных?

Источник данных должен содержать как минимум один набор данных. Убедитесь, что в нём есть хотя бы одна запись перед запуском операции слияния.

### Что происходит, если у источника данных неверный формат?

Если содержимое не распознаётся как один из поддерживаемых форматов, генерируется `NotSupportedException`. Если формат распознан, но некорректен, генерируется `InvalidDataException`. Текст исключения содержит информацию о месте ошибки.

### Можно ли использовать сгенерированную презентацию после возврата из обработчика?

Презентация, передаваемая в обработчик `MergeToMultiplePresentations`, принадлежит слиянию почты и освобождается после возврата обработчика. Сохраните её или скопируйте необходимый контент внутри обработчика и не сохраняйте и не освобождайте её самостоятельно.

### Вызывается ли обработчик параллельно?

Нет. Сгенерированные презентации обрабатываются последовательно в вызывающем потоке. В любой момент в памяти находится только одна презентация, что делает этот подход подходящим для больших объёмов данных.

### Что происходит, если внутри обработчика возникает исключение?

Операция слияния останавливается, а исключение передаётся вызывающему без изменений. Уже обработанные презентации не затрагиваются, а оставшиеся наборы данных не обрабатываются.

### Можно ли использовать значения полей для формирования имён выходных файлов?

Да. Обработчик получает текущий набор данных через свои аргументы. Используйте `GetText` для получения полей и формирования имени файла для каждой сгенерированной презентации. Убедитесь, что значения подходят для имён файлов в вашей целевой среде.
