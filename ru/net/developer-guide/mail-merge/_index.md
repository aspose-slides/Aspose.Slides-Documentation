## **Слияние почты в презентациях PowerPoint**

Aspose.Slides for .NET позволяет автоматически создавать презентации PowerPoint, используя шаблон и источник данных. Mail Merge заполняет заполнители шаблона данными и создает либо одну презентацию, содержащую повторяющиеся слайды шаблона для каждого набора данных, либо отдельную презентацию для каждого набора данных.

Эта возможность полезна для создания каталогов продукции, персонализированных презентаций, отчетов, сертификатов, предложений, прайс‑листов и других документов, где структура презентации остаётся одинаковой, а содержание меняется.

## **Как работает Mail Merge**

Mail Merge использует презентацию PowerPoint в качестве шаблона и заменяет заполнители значениями из источника данных.

![Mail Merge workflow](mail-merge-workflow.png)

Заполнитель — это имя поля, заключённое в двойные фигурные скобки, например `{{title}}` или `{{price}}`. Заполнители могут находиться в тексте фигур, ячейках таблиц, сгруппированных фигурах и заметках к докладчику.

Например, в шаблоне слайда может быть следующий текст:

- `Product: {{title}}`
- `Price: {{price}}`
- `Description: {{description}}`

Когда источник данных содержит такие значения:

| Поле | Значение |
|---|---|
| title | Laptop X1 |
| price | $999 |
| description | 14-inch display, 16 GB RAM |

Mail Merge заменяет заполнители соответствующими значениями, получая слайд с реальной информацией о продукте.

Имена полей нечувствительны к регистру, поэтому `{{title}}` и `{{Title}}` относятся к одному и тому же полю.

Применяются следующие правила замены заполнителей:

- Заполнители заменяются на слайдах, включая сгруппированные фигуры и ячейки таблиц, а также в заметках к докладчику.
- Заполнители на мастер‑слайдах и слайдах‑макетах не заменяются.
- Заполнитель, поле которого отсутствует в наборе данных, остаётся без изменений.
- Пустое значение поля заменяет свой заполнитель пустой строкой.
- Вставляемый текст наследует форматирование первого символа заполнителя.
- Значения не должны содержать текст заполнителя, иначе вставленный текст может быть обработан повторно и заменён другим полем.

Исходный шаблон презентации не изменяется во время операции слияния и должен содержать как минимум один слайд.

## **Поддерживаемые источники данных**

Mail Merge поддерживает два способа предоставления данных:

- Создать источник данных программно с помощью `IMailMergeDataSource`.
- Прочитать данные из файла или потока CSV, XLSX, JSON или XML.

Формат данных определяется по содержимому, а не по расширению файла. Поддерживаются потоки без возможности перемещения указателя.

Источник данных должен содержать как минимум один набор данных. Каждый набор представляет одну копию шаблона, заполняемую его значениями.

Если содержимое данных не может быть распознано как поддерживаемый формат, выбрасывается `NotSupportedException`. Если содержимое распознано, но не соответствует требованиям формата, выбрасывается `InvalidDataException`. Сообщение исключения содержит местоположение ошибки в данных.

### **JSON**

JSON‑источник данных должен иметь корневой объект, содержащий массив `sets`. Каждый элемент массива представляет набор данных и должен содержать массив `fields`. Каждое поле должно иметь строки `name` и `value`.

Необязательное свойство `version` должно быть `"1.0"`, а необязательное свойство `type` поля должно быть `"text"`. Имена свойств чувствительны к регистру. Неизвестные свойства игнорируются.

JSON‑данные читаются как UTF‑8 или как UTF‑16, если данные начинаются с маркера порядка байтов (BOM).

В следующем примере содержатся два набора данных:

```json
{
  "version": "1.0",
  "sets": [
    {
      "fields": [
        { "name": "title", "value": "Laptop X1" },
        { "name": "price", "value": "$999" }
      ]
    },
    {
      "fields": [
        { "name": "title", "value": "Tablet S2" },
        { "name": "price", "value": "$499" }
      ]
    }
  ]
}
```

### **XML**

XML‑источник данных должен иметь корневой элемент `template`, содержащий элемент `sets`. Каждый элемент `set` содержит элементы `field`, и каждый `field` должен включать элементы `name` и `value`.

Пустой элемент `value` рассматривается как пустая строка. Имена элементов чувствительны к регистру. Неизвестные элементы и комментарии игнорируются. Кодировка определяется объявлением XML. Определения типа документа (DTD) не допускаются.

```xml
<?xml version="1.0" encoding="utf-8"?>
<template>
  <sets>
    <set>
      <field>
        <name>title</name>
        <value>Laptop X1</value>
      </field>
      <field>
        <name>price</name>
        <value>$999</value>
      </field>
    </set>
    <set>
      <field>
        <name>title</name>
        <value>Tablet S2</value>
      </field>
      <field>
        <name>price</name>
        <value>$499</value>
      </field>
    </set>
  </sets>
</template>
```

### **CSV**

CSV‑данные используют точку с запятой в качестве разделителя значений.

Первая строка содержит имена полей и заканчивается на первом пустом имени поля. Каждая последующая строка представляет один набор данных. Данные оканчиваются первой пустой строкой.

Применяются следующие правила:

- Отсутствующие значения в конце строки рассматриваются как пустые строки.
- Значения, превышающие определённые имена полей, игнорируются.
- Значение, содержащее точку с запятой, кавычку или разрыв строки, должно быть заключено в кавычки.
- Кавычки внутри кавычного значения удваиваются.
- Данные читаются как UTF‑8 или как UTF‑16, если они начинаются с BOM.

Пример:

```csv
title;price;description
Laptop X1;$999;"14"" display; 16 GB RAM"
Tablet S2;$499;
```

### **XLSX**

XLSX‑данные читаются с первого листа рабочей книги.

Рабочий лист следует тем же правилам, что и CSV:

- Первая строка содержит имена полей и заканчивается на первой пустой ячейке.
- Каждая последующая строка представляет один набор данных.
- Данные оканчиваются первой пустой строкой.
- Пустые ячейки рассматриваются как пустые строки.
- Числовые значения преобразуются в текст с использованием инвариантной культуры.

## **Создание единой презентации**

Метод `MergeToSinglePresentation` создаёт одну презентацию, содержащую копию слайдов шаблона для каждого набора данных. Каждая копия заполняется соответствующими данными.

Порядок наборов данных определяет порядок групп слайдов в полученной презентации.

### **Слияние данных из файла**

В следующем примере загружается шаблон и JSON‑файл данных, создаётся единственная презентация со слайдами всех наборов и сохраняется результат.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, "products.json"))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

Данные также могут быть прочитаны из потока. Поток читается, начиная с текущей позиции, и не закрывается операцией Mail Merge.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xml"))
using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, data))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

### **Создание источника данных в коде**

Вы можете построить источник данных программно, используя `MailMergeDataSource` и `MailMergeDataSet`. Добавьте набор данных для каждой записи и определите его поля методом `AddText`.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet laptop = source.AddDataSet();
laptop.AddText("title", "Laptop X1");
laptop.AddText("price", "$999");

IMailMergeDataSet tablet = source.AddDataSet();
tablet.AddText("title", "Tablet S2");
tablet.AddText("price", "$499");

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, source))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

В этом примере слайды шаблона повторяются дважды: один раз для ноутбука и один раз для планшета. Заполнители заполняются значениями, определёнными в каждом наборе данных.

## **Создание нескольких презентаций**

Если требуется отдельная презентация для каждого набора данных, используйте метод `MergeToMultiplePresentations`.

Этот метод последовательно обрабатывает наборы данных, создаёт презентацию из шаблона, заполняет её текущими данными и передаёт полученную презентацию обработчику.

Обработчик вызывается один раз для каждого набора данных в исходном порядке.

### **Сохранение каждой презентации**

В следующем примере данные читаются из CSV‑файла, а каждая сгенерированная презентация сохраняется как отдельный файл.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.csv",
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

Свойство `args.Index` содержит нулевой индекс текущего набора данных. В примере оно используется для формирования последовательных имён файлов, начиная с `product_1.pptx`.

Данные также могут быть прочитаны из потока:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xlsx"))
using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        data,
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

### **Использование значений набора данных для имен файлов**

Обработчик получает как сгенерированную презентацию, так и информацию о наборе данных, использованном для её создания. Вы можете использовать значения полей набора данных для построения осмысленных имён файлов.

Например, следующий код сохраняет каждую презентацию, используя название продукта:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string title = args.DataSet.GetText("title");
            string fileName = title != null
                ? title
                : "product_" + (args.Index + 1);

            presentation.Save(fileName + ".pptx", SaveFormat.Pptx);
        });
}
```

Свойство `DataSet` возвращает набор данных, использованный для заполнения текущей презентации. Метод `GetText` получает значение указанного поля или `null`, если поле отсутствует.

Это позволяет использовать значения данных для именования файлов, организации вывода или дополнительной обработки в обработчике.

## **Обработка сгенерированных презентаций**

`MergeToMultiplePresentations` использует делегат `MailMergedPresentationHandler` для обработки каждой сгенерированной презентации.

Обработчик получает два аргумента:

- `presentation` — презентация, созданная из шаблона и заполненная текущим набором данных.
- `args` — информация о сгенерированной презентации, включая индекс набора данных и сам набор данных.

Сгенерированная презентация принадлежит операции Mail Merge и уничтожается сразу после возврата обработчика. Поэтому её необходимо сохранить или скопировать нужные данные внутри обработчика. Не сохраняйте ссылку на неё после возврата обработчика и не уничтожайте её вручную.

Обработчик выполняется в вызывающем потоке, одна презентация за раз, в порядке наборов данных. В любой момент в памяти хранится только одна сгенерированная презентация, что делает такой подход пригодным для обработки больших источников данных без одновременного удерживания всех презентаций в памяти.

Если обработчик генерирует исключение, операция Mail Merge прекращается, и исключение передаётся вызывающему без изменений. Уже обработанные презентации остаются без изменений, а остальные наборы данных не обрабатываются.

В следующем примере сгенерированные презентации сохраняются в выделенный каталог:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

string outputFolder = "output";
Directory.CreateDirectory(outputFolder);

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string path = Path.Combine(
                outputFolder,
                "product_" + (args.Index + 1) + ".pptx");

            presentation.Save(path, SaveFormat.Pptx);
        });
}
```

## **Работа с данными Mail Merge**

Класс `MailMergeDataSource` представляет упорядоченную коллекцию наборов данных. Его можно использовать для создания данных в коде, проверки количества наборов и доступа к отдельным наборам по индексу.

### **Получение количества наборов данных**

Свойство `Count` возвращает количество наборов данных в источнике.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine("Presentations to create: " + source.Count);
```

### **Доступ к набору данных по индексу**

Свойство `Item(int)` предоставляет доступ к набору данных по указанному нулевому индексу.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine(source[1].GetText("title"));
```

В этом примере извлекается название второго набора данных.

### **Добавление текстовых полей**

Метод `AddText` добавляет именованное текстовое поле в набор данных. Значение поля заменяет все соответствующие заполнители в шаблоне.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet dataSet = source.AddDataSet();
dataSet.AddText("title", "Laptop X1");
dataSet.AddText("subtitle", string.Empty);
```

Пустое значение удаляет соответствующий заполнитель из полученного текста. Если поле не добавлено в набор данных, заполнитель остаётся без изменений.

### **Чтение текстовых полей**

Метод `GetText` получает значение поля по имени. Имена полей нечувствительны к регистру.

```csharp
IMailMergeDataSet dataSet = source[0];

string title = dataSet.GetText("title");
string price = dataSet.GetText("price");
```

Если поле не существует или указанное имя поля равно `null`, `GetText` возвращает `null`.

Mail Merge в Aspose.Slides for .NET предоставляет удобный способ генерации презентаций на основе данных из переиспользуемого шаблона.

Вы можете использовать его для:

- Заполнения шаблонов презентаций значениями из источников данных.
- Создания единой презентации с повторяющимися слайдами шаблона для нескольких наборов данных.
- Создания отдельной презентации для каждого набора данных.
- Чтения данных из файлов CSV, XLSX, JSON и XML или потоков.
- Построения источников данных непосредственно в коде.
- Последовательной обработки и сохранения сгенерированных презентаций с помощью обработчика.

Комбинируя переиспользуемые шаблоны со структурированными данными, вы можете автоматизировать создание большого количества презентаций, сохраняя отдельными дизайн шаблона и логику обработки данных.

## **Часто задаваемые вопросы**

**Могу ли я использовать один и тот же заполнитель несколько раз в шаблоне?**

Да. Каждый экземпляр заполнителя с совпадающим именем поля заменяется соответствующим значением из текущего набора данных.

**Являются ли имена полей чувствительными к регистру?**

Нет. Имена заполнителей и полей данных нечувствительны к регистру. Например, `{{title}}`, `{{Title}}` и `{{TITLE}}` относятся к одному полю.

**Что происходит, если в наборе данных отсутствует поле, требуемое заполнителем?**

Если набор данных не содержит поля, на которое ссылается заполнитель, этот заполнитель остаётся без изменений в сгенерированной презентации.

**Что происходит, если у поля пустое значение?**

Пустое значение поля заменяет заполнитель пустой строкой. Текст заполнителя удаляется, и на его месте нет текста.

**Могу ли я сохранить форматирование заполнителя при замене?**

Текст‑замена наследует форматирование первого символа заполнителя. Задайте нужное форматирование текста заполнителя в шаблоне до выполнения слияния.

**Заменяет ли Mail Merge заполнители на мастер‑слайдах или слайдах‑макетах?**

Нет. Mail Merge заменяет заполнители только в поддерживаемом содержимом слайдов презентации, включая фигуры, сгруппированные фигуры, ячейки таблиц и заметки к докладчику. Заполнители на мастер‑и макет‑слайдах не заменяются.

**Изменяется ли шаблон презентации во время слияния?**

Нет. Исходный шаблон не изменяется операцией слияния. Его можно многократно использовать для генерации презентаций из разных источников данных.

**Могу ли я генерировать отдельную презентацию для каждого набора данных?**

Да. Используйте `MergeToMultiplePresentations` и сохраняйте каждую сгенерированную презентацию внутри обработчика. Обработчик вызывается последовательно для каждого набора данных.

**Могу ли я объединить все наборы данных в одну презентацию?**

Да. Используйте `MergeToSinglePresentation`. Он создаёт одну итоговую презентацию, содержащую копию слайдов шаблона для каждого набора данных в порядке их следования в источнике.

**Можно ли использовать источник данных без сохранения его в файл?**

Да. Вы можете создать `MailMergeDataSource` в коде, добавить наборы данных и заполнить поля с помощью `AddText`. Это удобно, когда данные уже доступны в вашем приложении.

**Определяет ли Mail Merge формат данных по расширению файла?**

Нет. Формат данных определяется содержимым, поэтому поддерживаемый источник данных не обязан иметь определённое расширение файла.

**Можно ли читать данные из потока, который не поддерживает перемещение указателя?**

Да. Mail Merge поддерживает неблокирующие (non‑seekable) потоки.

**Что происходит, если источник данных пуст или не содержит наборов данных?**

Источник данных должен содержать как минимум один набор. Убедитесь, что он включает хотя бы одну запись перед началом операции слияния.

**Что происходит, если у источника данных неверный формат?**

Если содержимое не распознаётся как один из поддерживаемых форматов, генерируется `NotSupportedException`. Если формат распознан, но структура неверна, генерируется `InvalidDataException`. Сообщение исключения включает информацию о месте ошибки.

**Могу ли я использовать сгенерированную презентацию после возврата обработчика?**

Презентация, передаваемая в обработчик `MergeToMultiplePresentations`, принадлежит Mail Merge и уничтожается после возврата обработчика. Сохраните её или скопируйте нужные данные внутри обработчика и не сохраняйте ссылку на неё после завершения.

**Вызывается ли обработчик параллельно?**

Нет. Презентации обрабатываются последовательно, в вызывающем потоке. В любой момент в памяти находится только одна сгенерированная презентация, что позволяет обрабатывать большие источники данных без одновременного удерживания всех презентаций.

**Что происходит, если внутри обработчика возникает исключение?**

Операция слияния останавливается, и исключение передаётся вызывающему без изменений. Уже обработанные презентации остаются без изменений, а оставшиеся наборы данных не обрабатываются.

**Могу ли я использовать значения полей для формирования имён файлов вывода?**

Да. Обработчик получает текущий набор данных через свои параметры. Используйте `GetText` для получения полей и формирования имени файла для каждой сгенерированной презентации. Убедитесь, что полученные значения допустимы для имён файлов в вашей целевой среде.
