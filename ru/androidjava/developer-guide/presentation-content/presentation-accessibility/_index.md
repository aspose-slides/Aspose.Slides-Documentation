## **Введение**

Альтернативный текст помогает людям, использующим вспомогательные технологии, понять значение изображений, диаграмм и других информативных фигур. Эта статья объясняет, как считывать и обновлять заголовки и описания альтернативного текста с помощью Aspose.Slides for Android via Java, различать описания доступности и имена фигур, используемые в коде, и проверять, помечена ли фигура как декоративная.

Эти функции поддерживают доступность презентаций, но не гарантируют её. Порядок чтения, контраст цветов, читаемость текста и другие требования доступности также требуют проверки.

## **Управление заголовками и описаниями альтернативного текста**

Используйте альтернативный текст, чтобы объяснить значение изображений, диаграмм и других информативных фигур людям, которые их не видят. Ниже перечисленные методы и содержимое служат разным целям:

| Метод или контент | Назначение |
| --- | --- |
| [getAlternativeTextTitle](https://reference.aspose.com/slides/ru/androidjava/com.aspose.slides/ishape/#getAlternativeTextTitle--) | Краткий заголовок для альтернативного описания. |
| [getAlternativeText](https://reference.aspose.com/slides/ru/androidjava/com.aspose.slides/ishape/#getAlternativeText--) | Осмысленное описание содержимого фигуры или её назначения в контексте слайда. |
| [getName](https://reference.aspose.com/slides/ru/androidjava/com.aspose.slides/ishape/#getName--) | Имя фигуры, которое код может использовать для поиска конкретной фигуры в презентации. |
| Visible text | Отображаемый на слайде текст, например текст фигуры или заголовок и подписи диаграммы. Обновление альтернативного текста не меняет это содержимое. |

Когда презентацию используют повторно как шаблон, код может находить фигуру по имени, возвращаемому методом [getName](https://reference.aspose.com/slides/ru/androidjava/com.aspose.slides/ishape/#getName--), перед тем как обновлять её. Это имя служит иной цели, чем альтернативный текст, который объясняет, что визуальный элемент передаёт читателю. Поиск по имени позволяет авторам улучшать или переводить описания, не меняя способ, которым код ищет фигуру. Имена могут быть изменены и не гарантируют уникальности, поэтому проверяйте, что имя соответствует ожидаемой фигуре; см. [Определение и поиск фигур](/slides/ru/androidjava/shape-manipulations/#identify-and-find-shapes).

В следующем примере требуется файл `input.pptx` с изображением входа в офис в качестве первой фигуры на первом слайде. Изображение не должно быть помечено как декоративное. Пример считывает и выводит текущий заголовок и описание альтернативного текста, обновляет оба значения и сохраняет презентацию как `output.pptx`. Подгоните формулировки под реальное изображение и передаваемую им информацию.

```java
import com.aspose.slides.*;

Presentation presentation = new Presentation("input.pptx");
try {
    IShape shape = presentation.getSlides().get_Item(0).getShapes().get_Item(0);

    System.out.println("Alternative text title: " + shape.getAlternativeTextTitle());
    System.out.println("Alternative text description: " + shape.getAlternativeText());

    shape.setAlternativeTextTitle("Office entrance");
    shape.setAlternativeText("The office entrance has a wheelchair ramp to the right of the steps.");

    presentation.save("output.pptx", SaveFormat.Pptx);
} finally {
    presentation.dispose();
}
```

Добавление лишь альтернативного текста не гарантирует доступность презентации или соответствие стандартам доступности. Проверьте описания на точность и уместность, а также проверьте порядок чтения, контраст цветов, читаемость текста и другие требования доступности. Информативные визуальные элементы не должны быть помечены как декоративные; в следующем разделе показано, как проверить [isDecorative](https://reference.aspose.com/slides/ru/androidjava/com.aspose.slides/ishape/#isDecorative--).

## **Отметить как декоративную**

Отметка как декоративная помечает исключительно декоративные визуальные элементы, чтобы считыватели экрана пропускали их, уменьшая шум и сохраняя фокус на значимом содержимом. Применяйте её к фонам, орнаментам и разделителям — никогда к диаграммам, значкам или изображениям, передающим информацию. Aspose.Slides предоставляет этот флаг для обнаружения и проверки, позволяя осуществлять автоматические проверки доступности и очистку.

![Отметить как декоративную](mark_as_decorative.png)

Следующий пример кода показывает, как определить, помечена ли фигура как декоративная.

```java
import com.aspose.slides.*;

Presentation presentation = new Presentation("sample.pptx");
try {
    IShape shape = presentation.getSlides().get_Item(0).getShapes().get_Item(0);
    System.out.println("Is shape decorative: " + shape.isDecorative());
} finally {
    presentation.dispose();
}
```

## **FAQ**

**Что следует помещать в заголовок и описание альтернативного текста?**

Используйте короткий заголовок, чтобы идентифицировать объект, и описание, чтобы объяснить информацию, которую визуальный элемент передаёт в контексте слайда. Для диаграммы опишите соответствующую тенденцию или сравнение, а не просто указывайте «chart».

**Стоит ли использовать альтернативный текст для поиска фигур в шаблоне?**

Предпочтительно находить фигуру по имени, возвращаемому методом [getName](https://reference.aspose.com/slides/ru/androidjava/com.aspose.slides/ishape/#getName--), и проверять, что это ожидаемая фигура. Альтернативный текст может быть изменён или переведён, что может нарушить работу кода, ищущего точное описание; см. [Определение и поиск фигур](/slides/ru/androidjava/shape-manipulations/).

**Когда следует помечать фигуру как декоративную?**

Используйте декоративный флаг для визуальных элементов, не добавляющих информации, таких как орнаментальные украшения. Изображения и диаграммы, передающие смысл, требуют соответствующего описания вместо этого.

**Добавление альтернативного текста делает презентацию полностью доступной?**

Нет. Альтернативный текст охватывает лишь часть вопросов доступности. Также проверяйте порядок чтения, контраст цветов, читаемость текста и другие применимые требования; установка только этих свойств не обеспечивает соответствие.
