## **ادغام نامه در ارائه‌های PowerPoint**

Aspose.Slides for .NET به شما امکان می‌دهد ارائه‌های PowerPoint را به‌صورت خودکار با استفاده از یک الگو و منبع داده تولید کنید. ادغام نامه جایگزین‌کنندهٔ متغیرهای الگو با داده‌ها می‌شود و یا یک ارائهٔ تک‌تکه شامل اسلایدهای تکراری برای هر مجموعه داده یا یک ارائهٔ جداگانه برای هر مجموعه داده ایجاد می‌کند.

این قابلیت برای تولید کاتالوگ‌های محصول، ارائه‌های شخصی‌سازی‌شده، گزارش‌ها، گواهینامه‌ها، پیشنهادات، لیست قیمت‌ها و سایر اسنادی که ساختار ارائه ثابت است ولی محتوا متفاوت، مفید است.

## **چگونه ادغام نامه کار می‌کند**

ادغام نامه از یک ارائهٔ PowerPoint به‌عنوان الگو استفاده می‌کند و متغیرها را با مقادیر منبع داده جایگزین می‌کند.

![گردش کار ادغام نامه](mail-merge-workflow.png)

یک متغیر، نام فیلدی است که داخل دو کروشهٔ منحنی قرار دارد، مانند `{{title}}` یا `{{price}}`. متغیرها می‌توانند در متن اشکال، سلول‌های جدول، اشکال گروهی و یادداشت‌های سخنران قرار گیرند.

به‌عنوان مثال، یک اسلاید الگو ممکن است متن زیر را داشته باشد:

- `Product: {{title}}`
- `Price: {{price}}`
- `Description: {{description}}`

وقتی منبع داده مقادیر زیر را داشته باشد:

| فیلد | مقدار |
|---|---|
| title | Laptop X1 |
| price | $999 |
| description | 14-inch display, 16 GB RAM |

ادغام نامه متغیرها را با مقادیر متناظر جایگزین می‌کند و اسلایدی با اطلاعات واقعی محصول تولید می‌شود.

نام فیلدها حساس به حروف کوچک و بزرگ نیستند، بنابراین `{{title}}` و `{{Title}}` به یک فیلد اشاره دارند.

قواعد زیر هنگام جایگزینی متغیرها اعمال می‌شود:

- متغیرها در اسلایدها، از جمله اشکال گروهی و سلول‌های جدول، و در یادداشت‌های سخنران جایگزین می‌شوند.
- متغیرهای موجود در اسلایدهای مستر و اسلایدهای طرح‌بندی جایگزین نمی‌شوند.
- متغیرهایی که فیلد مربوطه در مجموعه داده وجود ندارد، دست‌نخورده می‌مانند.
- مقدار خالی فیلد، متغیر را با یک رشتهٔ خالی جایگزین می‌کند.
- متن وارد شده، قالب‌بندی کاراکتر اول متغیر را به ارث می‌برد.
- مقادیر نباید شامل متن متغیر باشند، زیرا ممکن است متن وارد شده دوباره پردازش شود و توسط فیلد دیگری جایگزین شود.

ارائهٔ الگوی اصلی در طول عملیات ادغام تغییر نمی‌کند و باید حداقل یک اسلاید داشته باشد.

## **منابع دادهٔ پشتیبانی‌شده**

ادغام نامه دو روش برای تأمین داده‌ها پشتیبانی می‌کند:

- ایجاد منبع داده به‌صورت برنامه‌نویسی با استفاده از `IMailMergeDataSource`.
- خواندن داده‌ها از فایل یا جریان CSV، XLSX، JSON یا XML.

قالب داده بر اساس محتوا شناسایی می‌شود، نه بر اساس پسوند فایل. جریان‌هایی که از جستجو (seeking) پشتیبانی نمی‌کنند نیز پذیرفته می‌شوند.

منبع داده باید حداقل یک مجموعه داده داشته باشد. هر مجموعه داده نمایانگر یک کپی از الگو برای پر شدن با مقادیر آن است.

اگر محتوای داده به‌عنوان یک قالب پشتیبانی‌شده شناسایی نشود، `NotSupportedException` پرتاب می‌شود. اگر محتوا شناسایی شود اما با الزامات قالب سازگار نباشد، `InvalidDataException` پرتاب می‌شود. پیام استثناء محل خطا در داده را شامل می‌شود.

### **JSON**

منبع دادهٔ JSON باید دارای یک شی ریشه‌ای باشد که آرایهٔ `sets` را شامل شود. هر عنصر این آرایه نمایانگر یک مجموعه داده است و باید آرایهٔ `fields` را داشته باشد. هر فیلد باید رشتهٔ `name` و `value` داشته باشد.

خاصیت اختیاری `version` باید `"1.0"` باشد و خاصیت اختیاری `type` یک فیلد باید `"text"` باشد. نام خصوصیات به حروف کوچک و بزرگ حساس هستند. خصوصیات ناشناخته نادیده گرفته می‌شوند.

داده‌های JSON به صورت UTF-8 خوانده می‌شوند یا به‌عنوان UTF-16 زمانی که داده با علامت ترتیب بایت (BOM) شروع شود.

مثال زیر دو مجموعه داده دارد:

```json
{
  "version": "1.0",
  "sets": [
    {
      "fields": [
        { "name": "title", "value": "Laptop X1" },
        { "name": "price", "value": "$999" }
      ]
    },
    {
      "fields": [
        { "name": "title", "value": "Tablet S2" },
        { "name": "price", "value": "$499" }
      ]
    }
  ]
}
```

### **XML**

منبع دادهٔ XML باید دارای عنصر ریشه‌ای `template` باشد که عنصر `sets` را شامل شود. هر عنصر `set` شامل عناصر `field` است و هر فیلد باید عناصر `name` و `value` را داشته باشد.

عنصر `value` خالی به‌عنوان رشتهٔ خالی در نظر گرفته می‌شود. نام عناصر به حروف کوچک و بزرگ حساس هستند. عناصر و نظرات ناشناخته نادیده گرفته می‌شوند. کدگذاری توسط اعلان XML تعیین می‌شود. تعاریف نوع سند (DTD) مجاز نیستند.

```xml
<?xml version="1.0" encoding="utf-8"?>
<template>
  <sets>
    <set>
      <field>
        <name>title</name>
        <value>Laptop X1</value>
      </field>
      <field>
        <name>price</name>
        <value>$999</value>
      </field>
    </set>
    <set>
      <field>
        <name>title</name>
        <value>Tablet S2</value>
      </field>
      <field>
        <name>price</name>
        <value>$499</value>
      </field>
    </set>
  </sets>
</template>
```

### **CSV**

داده‌های CSV از نقطه‌ویرگول به‌عنوان جداکنندهٔ مقادیر استفاده می‌کنند.

سطر اول شامل نام فیلدها است و در اولین نام فیلد خالی پایان می‌یابد. هر سطر بعدی نمایانگر یک مجموعه داده است. داده‌ها در اولین سطر خالی خاتمه می‌یابند.

قواعد زیر اعمال می‌شود:

- مقادیر گمشده در انتهای سطر به‌عنوان رشتهٔ خالی درنظر گرفته می‌شوند.
- مقادیر فراتر از نام فیلدهای تعریف‌شده نادیده گرفته می‌شوند.
- مقداری که شامل نقطه‌ویرگول، علامت نقل‌قول یا شکست خط باشد باید داخل علامت نقل‌قول قرار گیرد.
- علامت‌های نقل‌قول داخل یک مقدار نقل‌قولی باید دو برابر شوند.
- داده‌ها به‌صورت UTF-8 یا UTF-16 (در صورت وجود BOM) خوانده می‌شوند.

مثال:

```csv
title;price;description
Laptop X1;$999;"14"" display; 16 GB RAM"
Tablet S2;$499;
```

### **XLSX**

داده‌های XLSX از اولین برگه کاری خوانده می‌شوند.

قوانین برگه کاری مشابه CSV است:

- سطر اول شامل نام فیلدها است و در اولین سلول خالی پایان می‌یابد.
- هر سطر بعدی نمایانگر یک مجموعه داده است.
- داده‌ها در اولین سطر خالی خاتمه می‌یابند.
- سلول‌های خالی به‌عنوان رشتهٔ خالی درنظر گرفته می‌شوند.
- مقادیر عددی با استفاده از فرهنگ ثابت (invariant culture) به متن تبدیل می‌شوند.

## **ایجاد یک ارائهٔ تک‌تکه**

متد `MergeToSinglePresentation` یک ارائهٔ تک‌تکه ایجاد می‌کند که شامل یک کپی از اسلایدهای الگو برای هر مجموعه داده است. هر کپی با داده‌های متناظر پر می‌شود.

ترتیب مجموعه داده‌ها ترتیب گروه‌های اسلاید در ارائهٔ نهایی را تعیین می‌کند.

### **ادغام داده‌ها از یک فایل**

مثال زیر یک الگو و یک فایل دادهٔ JSON را بارگذاری می‌کند، یک ارائهٔ تک‌تکه شامل اسلایدهای همهٔ مجموعه داده‌ها ایجاد می‌کند و نتیجه را ذخیره می‌نماید.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, "products.json"))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

داده‌ها می‌توانند از یک جریان نیز خوانده شوند. جریان از موقعیت فعلی خود خوانده می‌شود و توسط عملیات ادغام بسته نمی‌شود.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xml"))
using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, data))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

### **ایجاد منبع داده در کد**

می‌توانید یک منبع داده را به‌صورت برنامه‌نویسی با استفاده از `MailMergeDataSource` و `MailMergeDataSet` بسازید. برای هر رکورد یک مجموعه داده اضافه کنید و فیلدهای آن را با متد `AddText` تعریف کنید.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet laptop = source.AddDataSet();
laptop.AddText("title", "Laptop X1");
laptop.AddText("price", "$999");

IMailMergeDataSet tablet = source.AddDataSet();
tablet.AddText("title", "Tablet S2");
tablet.AddText("price", "$499");

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, source))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

در این مثال، اسلایدهای الگو دو بار تکرار می‌شوند: یک بار برای لپ‌تاپ و یک بار برای تبلت. متغیرها با مقادیری که در هر مجموعه داده تعریف شده‌اند پر می‌شوند.

## **ایجاد ارائه‌های متعدد**

اگر به یک ارائهٔ جداگانه برای هر مجموعه داده نیاز دارید، از متد `MergeToMultiplePresentations` استفاده کنید.

این متد مجموعه داده‌ها را یکی‌یکی پردازش می‌کند، برای هر مجموعه یک ارائه از الگو می‌سازد، آن را با دادهٔ جاری پر می‌کند و ارائهٔ حاصل را به یک هندلر می‌سپارد.

هندلر برای هر مجموعه داده یک‌بار فراخوانی می‌شود، به همان ترتیب اصلی داده.

### **ذخیرهٔ هر ارائه**

مثال زیر داده‌ها را از یک فایل CSV می‌خواند و هر ارائهٔ تولید شده را به‌عنوان یک فایل جداگانه ذخیره می‌کند.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.csv",
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

ویژگی `args.Index` ایندکس صفر‑پایهٔ مجموعه دادهٔ جاری را فراهم می‌کند. در مثال از آن برای تولید نام فایل‌های متوالی شروع از `product_1.pptx` استفاده شده است.

داده‌ها می‌توانند از یک جریان نیز خوانده شوند:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xlsx"))
using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        data,
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

### **استفاده از مقادیر مجموعه داده برای نام‌گذاری فایل‌ها**

هندلر هم ارائهٔ تولید شده و هم اطلاعات مربوط به مجموعه دادهٔ استفاده‌شده برای ایجاد آن را دریافت می‌کند. می‌توانید از مقادیر مجموعه داده برای ساخت نام‌های معنی‌دار فایل استفاده کنید.

به‌عنوان مثال، کد زیر هر ارائه را با استفاده از عنوان محصول ذخیره می‌کند:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string title = args.DataSet.GetText("title");
            string fileName = title != null
                ? title
                : "product_" + (args.Index + 1);

            presentation.Save(fileName + ".pptx", SaveFormat.Pptx);
        });
}
```

ویژگی `DataSet` مجموعه دادهٔ استفاده‌شده برای پر کردن ارائهٔ جاری را برمی‌گرداند. متد `GetText` مقدار فیلد مشخص‌شده را برمی‌گرداند یا اگر فیلد موجود نباشد `null` می‌دهد.

این امکان به شما اجازه می‌دهد تا از مقادیر داده برای نام‌گذاری فایل‌ها، سازمان‌دهی خروجی یا اعمال پردازش‌های اضافی در هندلر استفاده کنید.

## **مدیریت ارائه‌های تولید شده**

`MergeToMultiplePresentations` از delegate `MailMergedPresentationHandler` برای پردازش هر ارائهٔ تولید شده استفاده می‌کند.

هندلر دو پارامتر دریافت می‌کند:

- `presentation` — ارائه‌ای که از الگو ساخته شده و با مجموعه دادهٔ جاری پر شده است.
- `args` — اطلاعات دربارهٔ ارائهٔ تولید شده، شامل ایندکس مجموعه داده و خود مجموعه داده.

ارائهٔ تولید شده متعلق به عملیات ادغام است و بلافاصله پس از بازگشت هندلر از بین می‌رود. بنابراین باید داخل هندلر آن را ذخیره یا داده‌های مورد نیاز را کپی کنید. پس از بازگشت هندلر، نگه داشتن مرجع به آن یا خودتان آن را dispose نکنید.

هندلر در همان رشتهٔ فراخوانی اجرا می‌شود، یک ارائه در هر بار، به ترتیب مجموعه داده‌ها. در هر زمان فقط یک ارائهٔ تولید شده در حافظه نگه داشته می‌شود، بنابراین این روش برای پردازش منابع دادهٔ بزرگ بدون نگه‌داشتن تمام ارائه‌ها در حافظه مناسب است.

اگر هندلر یک استثناء پرتاب کند، عملیات ادغام متوقف می‌شود و استثناء بدون تغییر به فراخواننده منتقل می‌شود. ارائه‌های قبلاً پردازش‌شده تحت تأثیر قرار نمی‌گیرند و مجموعه داده‌های باقی‌مانده پردازش نمی‌شوند.

مثال زیر ارائه‌های تولید شده را در یک پوشهٔ اختصاصی ذخیره می‌کند:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

string outputFolder = "output";
Directory.CreateDirectory(outputFolder);

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string path = Path.Combine(
                outputFolder,
                "product_" + (args.Index + 1) + ".pptx");

            presentation.Save(path, SaveFormat.Pptx);
        });
}
```

## **کار با داده‌های ادغام نامه**

کلاس `MailMergeDataSource` نمایانگر یک مجموعهٔ ترتیبی از مجموعه داده‌ها است. می‌توانید از آن برای ساخت داده در کد، بررسی تعداد مجموعه داده‌ها و دسترسی به هر مجموعه داده بر اساس ایندکس استفاده کنید.

### **به‌دست آوردن تعداد مجموعه داده‌ها**

ویژگی `Count` تعداد مجموعه داده‌ها را در منبع برمی‌گرداند.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine("Presentations to create: " + source.Count);
```

### **دسترسی به یک مجموعه داده بر اساس ایندکس**

ویژگی `Item(int)` دسترسی به یک مجموعه داده در ایندکس صفر‑پایهٔ مشخص را فراهم می‌کند.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine(source[1].GetText("title"));
```

این مثال عنوان مجموعه دادهٔ دوم را بازیابی می‌کند.

### **افزودن فیلدهای متنی**

متد `AddText` یک فیلد متنی نام‌دار به یک مجموعه داده اضافه می‌کند. مقدار فیلد تمام متغیرهای مطابقت‌دار در الگو را جایگزین می‌کند.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet dataSet = source.AddDataSet();
dataSet.AddText("title", "Laptop X1");
dataSet.AddText("subtitle", string.Empty);
```

یک مقدار خالی، متغیر مربوطه را از متن نهایی حذف می‌کند. اگر فیلد به مجموعه داده اضافه نشود، متغیر دست‌نخورده می‌ماند.

### **خواندن فیلدهای متنی**

متد `GetText` مقدار یک فیلد را بر اساس نام برمی‌گرداند. نام فیلدها حساس به حروف بزرگ و کوچک نیستند.

```csharp
IMailMergeDataSet dataSet = source[0];

string title = dataSet.GetText("title");
string price = dataSet.GetText("price");
```

اگر فیلد وجود نداشته باشد یا نام فیلد `null` باشد، `GetText` `null` برمی‌گرداند.

## **خلاصه**

ادغام نامه در Aspose.Slides for .NET روشی آسان برای تولید ارائه‌های مبتنی بر داده از یک الگوی قابل استفادهٔ مجدد فراهم می‌کند.

می‌توانید از آن برای:

- پر کردن قالب‌های ارائه با مقادیر منبع داده.
- تولید یک ارائهٔ تک‌تکه شامل اسلایدهای تکراری برای چندین مجموعه داده.
- ایجاد یک ارائهٔ جداگانه برای هر مجموعه داده.
- خواندن داده‌ها از فایل‌ها یا جریان‌های CSV، XLSX، JSON و XML.
- ساخت منابع داده مستقیم در کد.
- پردازش و ذخیرهٔ ارائه‌های تولید شده به‌صورت ترتیبی با استفاده از یک هندلر.

با ترکیب الگوهای قابل استفادهٔ مجدد با داده‌های ساختاریافته، می‌توانید ایجاد تعداد زیادی ارائه را خودکار کنید در حالی که طراحی قالب و منطق پردازش داده جدا نگه داشته می‌شوند.

## **سوالات متداول**

**آیا می‌توانم از یک متغیر چندین بار در یک الگو استفاده کنم؟**

بله. هر رخداسی از متغیر با نام فیلد مطابقت‌دار با مقدار متناظر از مجموعه دادهٔ جاری جایگزین می‌شود.

**آیا نام فیلدها به حروف بزرگ و کوچک حساس هستند؟**

خیر. نام فیلدهای متغیر و داده‌ها به حروف بزرگ و کوچک حساس نیستند. برای مثال `{{title}}`، `{{Title}}` و `{{TITLE}}` به یک فیلد اشاره دارند.

**اگر یک فیلد در مجموعه داده موجود نباشد چه می‌شود؟**

اگر مجموعه داده فیلدی که توسط یک متغیر ارجاع داده شده باشد نداشته باشد، آن متغیر در ارائهٔ تولید شده دست‌نخورده می‌ماند.

**اگر یک فیلد مقدار خالی داشته باشد چه می‌شود؟**

مقدار خالی فیلد، متغیر را با یک رشتهٔ خالی جایگزین می‌کند. متن متغیر حذف می‌شود و جای چیزی نمی‌ماند.

**آیا می‌توانم قالب‌بندی متغیر را هنگام جایگزینی حفظ کنم؟**

متن جایگزین، قالب‌بندی کاراکتر اول متغیر را به ارث می‌برد. قبل از ادغام قالب‌بندی دلخواه را روی متن متغیر در الگو اعمال کنید.

**آیا ادغام نامه متغیرها را در اسلایدهای مستر یا طرح‌بندی جایگزین می‌کند؟**

خیر. ادغام نامه متغیرها را فقط در محتویات پشتیبانی‌شدهٔ اسلایدهای ارائه (اشکال، اشکال گروهی، سلول‌های جدول و یادداشت‌های سخنران) جایگزین می‌کند. متغیرهای موجود در اسلایدهای مستر و طرح‌بندی جایگزین نمی‌شوند.

**آیا ارائهٔ الگو در طول ادغام تغییر می‌کند؟**

خیر. ارائهٔ اصلی توسط عملیات ادغام تغییری نمی‌کند. می‌توانید از آن برای تولید ارائه‌های متعدد از همان منبع داده یا منابع دادهٔ متفاوت استفاده کنید.

**آیا می‌توانم برای هر مجموعه داده یک ارائهٔ جداگانه تولید کنم؟**

بله. از `MergeToMultiplePresentations` استفاده کنید و هر ارائهٔ تولید شده را داخل هندلر ذخیره کنید. هندلر به‌صورت ترتیبی برای هر مجموعه داده فراخوانی می‌شود.

**آیا می‌توانم تمام مجموعه داده‌ها را در یک ارائه ترکیب کنم؟**

بله. از `MergeToSinglePresentation` استفاده کنید. این متد یک ارائهٔ خروجی تک تولید می‌کند که شامل یک کپی از اسلایدهای الگو برای هر مجموعه داده، به ترتیب منبع داده است.

**آیا می‌توانم منبع داده را بدون ذخیره در فایل استفاده کنم؟**

بله. می‌توانید یک `MailMergeDataSource` را در کد بسازید، مجموعه داده‌ها را اضافه کنید و فیلدها را با `AddText` پر کنید. این مورد وقتی داده‌ها در برنامهٔ شما در دسترس هستند مفید است.

**آیا ادغام نامه قالب داده را از پسوند فایل تشخیص می‌دهد؟**

خیر. قالب داده از محتوا شناسایی می‌شود، بنابراین یک منبع دادهٔ پشتیبانی‌شده مجبور به استفاده از پسوند خاصی نیست.

**آیا می‌توانم داده‌ها را از یک جریان که از جستجو پشتیبانی نمی‌کند بخوانم؟**

بله. ادغام نامه از جریان‌های غیرقابل جستجو (non‑seekable) پشتیبانی می‌کند.

**اگر منبع داده خالی باشد یا مجموعه داده‌ای نداشته باشد چه می‌شود؟**

منبع داده باید حداقل یک مجموعه داده داشته باشد. پیش از شروع ادغام اطمینان حاصل کنید که حداقل یک رکورد وجود داشته باشد.

**اگر منبع داده قالب نامعتبری داشته باشد چه می‌شود؟**

اگر محتوا به‌عنوان یکی از قالب‌های پشتیبانی‌شده تشخیص داده نشود، `NotSupportedException` پرتاب می‌شود. اگر تشخیص داده شود اما قالب نادرست باشد، `InvalidDataException` پرتاب می‌شود. پیام استثناء شامل اطلاعاتی دربارهٔ محل خطا است.

**آیا می‌توانم پس از بازگشت هندلر از ارائهٔ تولید شده استفاده کنم؟**

ارائهٔ پاس داده‌شده به هندلر `MergeToMultiplePresentations` متعلق به ادغام نامه است و پس از بازگشت هندلر از بین می‌رود. داخل هندلر آن را ذخیره یا محتوای مورد نیاز را کپی کنید و پس از بازگشت، مرجع آن را نگه ندارید یا خودتان آن را dispose نکنید.

**آیا هندلر به‌صورت موازی فراخوانی می‌شود؟**

خیر. ارائه‌های تولید شده به‌صورت ترتیبی، بر روی رشتهٔ فراخوانی پردازش می‌شوند. در هر زمان فقط یک ارائهٔ تولید شده در حافظه نگه داشته می‌شود.

**اگر استثناء‌ای داخل هندلر رخ دهد چه می‌شود؟**

عملیات ادغام متوقف می‌شود و استثناء بدون تغییر به فراخواننده منتقل می‌شود. ارائه‌های قبلاً پردازش‌شده تحت تأثیر قرار نمی‌گیرند و مجموعه داده‌های باقی‌مانده پردازش نمی‌شوند.

**آیا می‌توانم از مقادیر فیلدها برای تولید نام فایل خروجی استفاده کنم؟**

بله. هندلر مجموعه دادهٔ جاری را از طریق آرگومان‌های خود فراهم می‌کند. می‌توانید با استفاده از `GetText` فیلدها را بازیابی کرده و یک نام فایل برای هر ارائهٔ تولید شده بسازید. مطمئن شوید که مقادیر برای نام‌گذاری فایل در محیط هدف شما معتبر هستند.
