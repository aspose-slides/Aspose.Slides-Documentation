# ادغام نامه در ارائه‌های پاورپوینت

Aspose.Slides for .NET به شما امکان می‌دهد که به‌صورت خودکار ارائه‌های پاورپوینت را با استفاده از یک قالب و یک منبع داده تولید کنید. ادغام نامه (Mail Merge) جاهای نگهدارنده قالب را با داده‌ها پر می‌کند و یا یک ارائهٔ تک ایجاد می‌کند که شامل اسلایدهای تکراری قالب برای هر مجموعه داده است یا یک ارائهٔ جداگانه برای هر مجموعه داده ایجاد می‌کند.

این قابلیت برای تولید کاتالوگ‌های محصول، ارائه‌های شخصی‌سازی‌شده، گزارش‌ها، گواهینامه‌ها، پیشنهادات، فهرست‌های قیمت و سایر اسنادی که ساختار ارائه ثابت می‌ماند ولی محتوا تغییر می‌کند، مفید است.

![ادغام نامه: قبل و بعد](mail-merge-before-after.png)


## نحوهٔ عملکرد ادغام نامه

ادغام نامه از یک ارائهٔ پاورپوینت به‌عنوان قالب استفاده می‌کند و جاهای نگهدارنده را با مقادیر منبع داده جایگزین می‌نماید.

![جریان کار ادغام نامه](mail-merge-workflow.png)

یک جاگیر (placeholder) نام فیلدی است که بین دو آکولاد دوتایی قرار می‌گیرد، مانند `{{title}}` یا `{{price}}`. جاگیرها می‌توانند در متن اشکال، سلول‌های جدول، اشکال گروهی و یادداشت‌های گوینده قرار گیرند.

به عنوان مثال، یک اسلاید قالب می‌تواند متن‌های زیر را داشته باشد:

- `Product: {{title}}`
- `Price: {{price}}`
- `Description: {{description}}`

وقتی منبع داده مقادیر زیر را داشته باشد:

| فیلد | مقدار |
|---|---|
| title | Laptop X1 |
| price | $999 |
| description | 14-inch display, 16 GB RAM |

ادغام نامه جاگیرها را با مقادیر متناظر جایگزین می‌کند و اسلایدی با اطلاعات واقعی محصول تولید می‌نماید.

نام فیلدها حساس به حروف کوچک و بزرگ نیستند، بنابراین `{{title}}` و `{{Title}}` به یک فیلد اشاره می‌کنند.

قوانین زیر هنگام جایگزینی جاگیرها اعمال می‌شود:

- جاگیرها در اسلایدها، از جمله اشکال گروهی و سلول‌های جدول، و در یادداشت‌های گوینده جایگزین می‌شوند.
- جاگیرهای موجود در اسلایدهای مستر و لایه‌بندی جایگزین نمی‌شوند.
- جاگیری که فیلد مربوطه در مجموعه داده وجود نداشته باشد، بدون تغییر می‌ماند.
- مقدار خالی فیلد، جاگیر را با رشتهٔ خالی جایگزین می‌کند.
- متن درج شده قالب‌بندی کاراکتر اول جاگیر را به ارث می‌برد.
- مقادیر نباید شامل متن جاگیر باشند، زیرا متن درج شده ممکن است دوباره پردازش شده و توسط فیلد دیگری جایگزین شود.

ارائهٔ قالب اصلی در طول عملیات ادغام تغییر نمی‌کند و باید حداقل یک اسلاید داشته باشد.

## منابع دادهٔ پشتیبانی‌شده

ادغام نامه دو روش برای فراهم کردن داده‌ها پشتیبانی می‌کند:

- ایجاد یک منبع داده به‌صورت برنامه‌نویسی با استفاده از `IMailMergeDataSource`.
- خواندن داده‌ها از یک فایل یا جریان CSV، XLSX، JSON یا XML.

قالب داده بر اساس محتوا تشخیص داده می‌شود، نه بر اساس پسوند فایل. جریان‌هایی که از جست‌وجو (seeking) پشتیبانی نمی‌کنند نیز پشتیبانی می‌شوند.

منبع داده باید حداقل یک مجموعه داده داشته باشد. هر مجموعه داده یک نسخه از قالب را که با مقادیر آن پر می‌شود، نمایندگی می‌کند.

اگر محتوای داده به‌عنوان یک قالب پشتیبانی‌شده شناسایی نشود، `NotSupportedException` پرتاب می‌شود. اگر محتوا شناسایی شد ولی با الزامات قالب سازگار نباشد، `InvalidDataException` پرتاب می‌شود. پیام استثنا شامل مکان خطا در داده است.

### JSON

منبع دادهٔ JSON باید یک شی ریشه داشته باشد که شامل آرایهٔ `sets` باشد. هر عنصر آرایه نمایندهٔ یک مجموعه داده است و باید آرایهٔ `fields` را شامل شود. هر فیلد باید یک رشتهٔ `name` و یک رشتهٔ `value` داشته باشد.

خاصیت اختیاری `version` باید `"1.0"` باشد و خاصیت اختیاری `type` یک فیلد باید `"text"` باشد. نام خاصیت‌ها حساس به حروف بزرگ/کوچک است. خاصیت‌های ناشناخته نادیده گرفته می‌شوند.

داده‌های JSON به‌صورت UTF-8 خوانده می‌شوند یا به‌صورت UTF-16 هنگامی که داده با علامت ترتیب بایت (BOM) شروع شود.

مثال زیر شامل دو مجموعه داده است:

```json
{
  "version": "1.0",
  "sets": [
    {
      "fields": [
        { "name": "title", "value": "Laptop X1" },
        { "name": "price", "value": "$999" }
      ]
    },
    {
      "fields": [
        { "name": "title", "value": "Tablet S2" },
        { "name": "price", "value": "$499" }
      ]
    }
  ]
}
```

### XML

منبع دادهٔ XML باید یک عنصر ریشهٔ `template` داشته باشد که شامل عنصر `sets` باشد. هر عنصر `set` شامل عناصر `field` است و هر فیلد باید عناصر `name` و `value` را داشته باشد.

یک عنصر `value` خالی به‌عنوان رشتهٔ خالی درنظر گرفته می‌شود. نام عناصر حساس به حروف بزرگ/کوچک هستند. عناصر و نظرات ناشناخته نادیده گرفته می‌شوند. رمزگذاری توسط اعلان XML تعیین می‌شود. تعریف‌های نوع سند (DTD) مجاز نیستند.

```xml
<?xml version="1.0" encoding="utf-8"?>
<template>
  <sets>
    <set>
      <field>
        <name>title</name>
        <value>Laptop X1</value>
      </field>
      <field>
        <name>price</name>
        <value>$999</value>
      </field>
    </set>
    <set>
      <field>
        <name>title</name>
        <value>Tablet S2</value>
      </field>
      <field>
        <name>price</name>
        <value>$499</value>
      </field>
    </set>
  </sets>
</template>
```

### CSV

داده‌های CSV از نقطه‌ویرگول به‌عنوان جداکنندهٔ مقادیر استفاده می‌کنند.

ردیف اول شامل نام فیلدها است و در اولین فیلد خالی پایان می‌یابد. هر ردیف بعدی نمایندهٔ یک مجموعه داده است. داده‌ها در اولین ردیف خالی پایان می‌یابند.

قوانین زیر اعمال می‌شود:

- مقادیر گمشده در انتهای یک ردیف به‌عنوان رشتهٔ خالی درنظر گرفته می‌شوند.
- مقادیری که بیش از نام فیلدهای تعریف‌شده باشد نادیده گرفته می‌شوند.
- مقداری که شامل نقطه‌ویرگول، علامت نقل قول یا شکست خط باشد، باید در داخل علامت نقل قول قرار گیرد.
- علامت‌های نقل قول داخل مقدار quoted باید دو بار نوشته شوند.
- داده‌ها به‌صورت UTF-8 خوانده می‌شوند یا به‌صورت UTF-16 هنگامی که با BOM شروع شود.

مثال:

```csv
title;price;description
Laptop X1;$999;"14"" display; 16 GB RAM"
Tablet S2;$499;
```

### XLSX

داده‌های XLSX از اولین worksheet خوانده می‌شوند.

قالب worksheet مشابه CSV است:

- ردیف اول شامل نام فیلدها است و در اولین سلول خالی پایان می‌یابد.
- هر ردیف بعدی نمایندهٔ یک مجموعه داده است.
- داده‌ها در اولین ردیف خالی پایان می‌یابند.
- سلول‌های خالی به‌عنوان رشتهٔ خالی درنظر گرفته می‌شوند.
- مقادیر عددی با استفاده از فرهنگ invariant به متن تبدیل می‌شوند.

## ایجاد یک ارائهٔ تک

متد `MergeToSinglePresentation` یک ارائهٔ تک ایجاد می‌کند که شامل یک کپی از اسلایدهای قالب برای هر مجموعه داده است. هر کپی با داده‌های مربوطه پر می‌شود.

ترتیب مجموعه داده‌ها، ترتیب گروه‌های اسلاید در ارائهٔ نهایی را تعیین می‌کند.

### ادغام داده‌ها از یک فایل

مثال زیر یک قالب و یک فایل دادهٔ JSON را بارگذاری می‌کند، یک ارائهٔ تک حاوی اسلایدهای تمام مجموعه داده‌ها ایجاد می‌کند و نتیجه را ذخیره می‌کند.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, "products.json"))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

داده‌ها می‌توانند از یک جریان نیز خوانده شوند. جریان از موقعیت فعلی خود خوانده می‌شود و توسط عملیات ادغام نامه بسته نمی‌شود.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xml"))
using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, data))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

### ایجاد یک منبع داده در کد

می‌توانید یک منبع داده را به‌صورت برنامه‌نویسی با استفاده از `MailMergeDataSource` و `MailMergeDataSet` بسازید. برای هر رکورد یک مجموعه داده اضافه کنید و فیلدهای آن را با متد `AddText` تعریف کنید.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet laptop = source.AddDataSet();
laptop.AddText("title", "Laptop X1");
laptop.AddText("price", "$999");

IMailMergeDataSet tablet = source.AddDataSet();
tablet.AddText("title", "Tablet S2");
tablet.AddText("price", "$499");

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
using (IPresentation result = mailMerge.MergeToSinglePresentation(template, source))
{
    result.Save("catalog.pptx", SaveFormat.Pptx);
}
```

در این مثال، اسلایدهای قالب دو بار تکرار می‌شوند: یک بار برای لپ‌تاپ و یک بار برای تبلت. جاگیرها با مقادیری که در هر مجموعه داده تعریف شده‌اند، پر می‌شوند.

## ایجاد ارائه‌های متعدد

اگر به یک ارائهٔ جداگانه برای هر مجموعه داده نیاز دارید، از متد `MergeToMultiplePresentations` استفاده کنید.

این متد مجموعه داده‌ها را یکی‌یکی پردازش می‌کند، یک ارائه از قالب می‌سازد، آن را با دادهٔ جاری پر می‌کند و ارائهٔ حاصل را به یک هندلر می‌سپارد.

هندلر برای هر مجموعه داده یک بار صدا زده می‌شود، به ترتیب اصلی داده‌ها.

### ذخیرهٔ هر ارائه

مثال زیر داده‌ها را از یک فایل CSV می‌خواند و هر ارائهٔ تولید شده را به صورت یک فایل جداگانه ذخیره می‌کند.

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.csv",
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

خواص `args.Index` نمایانگر ایندکس صفر‑پایهٔ مجموعه دادهٔ جاری است. در این مثال برای تولید نام‌های فایل متوالی از `product_1.pptx` استفاده می‌شود.

داده‌ها می‌توانند از یک جریان نیز خوانده شوند:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Stream data = File.OpenRead("products.xlsx"))
using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        data,
        (presentation, args) =>
        {
            presentation.Save(
                "product_" + (args.Index + 1) + ".pptx",
                SaveFormat.Pptx);
        });
}
```

### استفاده از مقادیر مجموعه داده برای نامگذاری فایل‌ها

هندلر هم ارائهٔ تولید شده و هم اطلاعات مربوط به مجموعه داده‌ای که برای ایجاد آن به‌کار رفته است را دریافت می‌کند. می‌توانید از مقادیر مجموعه داده برای ساخت نام‌های معنادار فایل استفاده کنید.

به عنوان مثال، کد زیر هر ارائه را با استفاده از عنوان محصول ذخیره می‌کند:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string title = args.DataSet.GetText("title");
            string fileName = title != null
                ? title
                : "product_" + (args.Index + 1);

            presentation.Save(fileName + ".pptx", SaveFormat.Pptx);
        });
}
```

خاصیت `DataSet` مجموعه دادهٔ استفاده‌شده برای پر کردن ارائهٔ جاری را برمی‌گرداند. متد `GetText` مقدار یک فیلد مشخص را برمی‌گرداند یا در صورت عدم وجود فیلد `null` برمی‌گرداند.

این امکان به شما اجازه می‌دهد تا از مقادیر داده برای نام‌گذاری فایل‌ها، سازماندهی خروجی یا اعمال پردازش‌های اضافی در هندلر استفاده کنید.

## مدیریت ارائه‌های تولید شده

`MergeToMultiplePresentations` از نمایندهٔ `MailMergedPresentationHandler` برای پردازش هر ارائهٔ تولید شده استفاده می‌کند.

هندلر دو آرگومان دریافت می‌کند:

- `presentation` — ارائه‌ای که از قالب ساخته شده و با مجموعه دادهٔ جاری پر شده است.
- `args` — اطلاعاتی دربارهٔ ارائهٔ تولید شده شامل ایندکس مجموعه داده و خود مجموعه داده.

ارائهٔ تولید شده متعلق به عملیات ادغام نامه است و بلافاصله پس از بازگشت هندلر از بین می‌رود. بنابراین باید آن را ذخیره کنید یا هر دادهٔ مورد نیاز را داخل هندلر کپی کنید. پس از بازگشت هندلر یا به‌صورت دستی آن را نازک نکنید.

هندلر در همان نخ فراخوان، یک ارائه در هر بار، به ترتیب مجموعه داده‌ها اجرا می‌شود. تنها یک ارائهٔ تولید شده در هر لحظه در حافظه نگه داشته می‌شود؛ بنابراین این روش برای پردازش منابع دادهٔ بزرگ بدون نیاز به نگه‌داری تمام ارائه‌ها در حافظه مناسب است.

اگر هندلر استثنایی پرتاب کند، عملیات ادغام نامه متوقف می‌شود و استثنا به‌طور یکسان به فراخوان منتقل می‌شود. ارائه‌های قبلاً پردازش‌شده تحت تأثیر قرار نمی‌گیرند و مجموعه داده‌های باقی‌مانده پردازش نمی‌شوند.

مثال زیر ارائه‌های تولید شده را در یک پوشهٔ اختصاصی ذخیره می‌کند:

```csharp
using Aspose.Slides;
using Aspose.Slides.MailMerge;
using System.IO;

string outputFolder = "output";
Directory.CreateDirectory(outputFolder);

MailMergeProcessor mailMerge = new MailMergeProcessor();

using (Presentation template = new Presentation("template.pptx"))
{
    mailMerge.MergeToMultiplePresentations(
        template,
        "products.json",
        (presentation, args) =>
        {
            string path = Path.Combine(
                outputFolder,
                "product_" + (args.Index + 1) + ".pptx");

            presentation.Save(path, SaveFormat.Pptx);
        });
}
```

## کار با داده‌های ادغام نامه

کلاس `MailMergeDataSource` یک مجموعهٔ مرتب از مجموعه داده‌ها را نشان می‌دهد. می‌توانید از آن برای ایجاد داده در کد، بررسی تعداد مجموعه داده‌ها و دسترسی به مجموعه داده‌های فردی بر اساس ایندکس استفاده کنید.

### دریافت تعداد مجموعه داده‌ها

خاصیت `Count` تعداد مجموعه داده‌ها در منبع را برمی‌گرداند.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine("Presentations to create: " + source.Count);
```

### دسترسی به یک مجموعه داده بر اساس ایندکس

خاصیت `Item(int)` اجازه دسترسی به یک مجموعه داده در ایندکس صفر‑پایه مشخص‌شده را می‌دهد.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

source.AddDataSet().AddText("title", "Laptop X1");
source.AddDataSet().AddText("title", "Tablet S2");

Console.WriteLine(source[1].GetText("title"));
```

این مثال عنوان مجموعه داده دوم را بازیابی می‌کند.

### افزودن فیلدهای متنی

متد `AddText` یک فیلد متنی نام‌دار را به یک مجموعه داده اضافه می‌کند. مقدار فیلد تمام جاگیرهای منطبق در قالب را جایگزین می‌کند.

```csharp
MailMergeDataSource source = new MailMergeDataSource();

IMailMergeDataSet dataSet = source.AddDataSet();
dataSet.AddText("title", "Laptop X1");
dataSet.AddText("subtitle", string.Empty);
```

یک مقدار خالی، جاگیر مربوطه را از متن نهایی حذف می‌کند. اگر فیلد به مجموعه داده اضافه نشود، جاگیر دست‌نخورده می‌ماند.

### خواندن فیلدهای متنی

متد `GetText` مقدار یک فیلد را بر اساس نام دریافت می‌کند. نام فیلدها حساس به حروف بزرگ/کوچک نیستند.

```csharp
IMailMergeDataSet dataSet = source[0];

string title = dataSet.GetText("title");
string price = dataSet.GetText("price");
```

اگر فیلد وجود نداشته باشد یا نام فیلد `null` باشد، `GetText` مقدار `null` را باز می‌گرداند.

## خلاصه

ادغام نامه در Aspose.Slides for .NET روشی راحت برای تولید ارائه‌های مبتنی بر داده از یک قالب قابل استفاده مجدد فراهم می‌کند.

می‌توانید از آن برای:

- پر کردن قالب‌های ارائه با مقادیر از منابع داده.
- تولید یک ارائهٔ تک حاوی اسلایدهای تکراری قالب برای مجموعه داده‌های متعدد.
- ایجاد یک ارائهٔ جداگانه برای هر مجموعه داده.
- خواندن داده‌ها از فایل‌ها یا جریان‌های CSV، XLSX، JSON و XML.
- ساخت منابع داده به‌صورت مستقیم در کد.
- پردازش و ذخیرهٔ ارائه‌های تولید شده به‌صورت متوالی با استفاده از یک هندلر.

با ترکیب قالب‌های قابل استفاده مجدد با داده‌های ساختاریافته، می‌توانید ایجاد تعداد زیادی از ارائه‌ها را خودکار کنید در حالی که طراحی قالب و منطق پردازش داده‌ها جدا نگه داشته می‌شوند.

## پرسش‌های متداول

### آیا می‌توانم یک جاگیر یکسان را چندین بار در یک قالب استفاده کنم؟

بله. هر بار ظاهر یک جاگیر با نام فیلد منطبق، با مقدار مربوطه از مجموعه دادهٔ جاری جایگزین می‌شود.

### آیا نام فیلدها به حروف بزرگ/کوچک حساس هستند؟

خیر. نام‌های جاگیر و فیلدهای داده حساس به حروف بزرگ/کوچک نیستند. به عنوان مثال `{{title}}`، `{{Title}}` و `{{TITLE}}` به یک فیلد اشاره می‌کنند.

### اگر یک فیلد در مجموعه داده وجود نداشته باشد چه می‌شود؟

اگر مجموعه داده فیلدی که توسط جاگیر اشاره شده باشد نداشته باشد، آن جاگیر در ارائهٔ تولید شده دست‌نخورده می‌ماند.

### اگر یک فیلد مقدار خالی داشته باشد چه می‌شود؟

مقدار خالی فیلد، جاگیر را با رشتهٔ خالی جایگزین می‌کند. متن جاگیر حذف می‌شود و جایگزینی ندارد.

### آیا می‌توانم قالب‌بندی یک جاگیر را هنگام جایگزینی حفظ کنم؟

متن جایگزین، قالب‌بندی کاراکتر اول جاگیر را به ارث می‌برد. قالب‌بندی دلخواه را قبل از ادغام بر روی متن جاگیر اعمال کنید.

### آیا ادغام نامه جاگیرها را در اسلایدهای مستر یا لایه‌بندی جایگزین می‌کند؟

خیر. ادغام نامه جاگیرها را در محتوای پشتیبانی‌شدهٔ اسلایدهای ارائه، شامل اشکال، اشکال گروهی، سلول‌های جدول و یادداشت‌های گوینده، جایگزین می‌کند. جاگیرهای موجود در اسلایدهای مستر و لایه‌بندی جایگزین نمی‌شوند.

### آیا قالب ارائه در طول ادغام تغییر می‌کند؟

خیر. قالب اصلی در طول عملیات ادغام تغییر نمی‌کند. می‌توانید آن را برای تولید ارائه‌های متعدد از همان منبع یا منابع داده مختلف دوباره استفاده کنید.

### آیا می‌توانم یک ارائهٔ جداگانه برای هر مجموعه داده تولید کنم؟

بله. از `MergeToMultiplePresentations` استفاده کنید و هر ارائهٔ تولید شده را داخل هندلر ذخیره کنید. هندلر به‌صورت متوالی برای هر مجموعه داده فراخوانی می‌شود.

### آیا می‌توانم تمام مجموعه داده‌ها را در یک ارائه ترکیب کنم؟

بله. از `MergeToSinglePresentation` استفاده کنید. این متد یک ارائهٔ خروجی تک ایجاد می‌کند که شامل یک کپی از اسلایدهای قالب برای هر مجموعه داده، به ترتیب منبع داده، است.

### آیا می‌توانم منبع داده را بدون ذخیره‌سازی در فایل استفاده کنم؟

بله. می‌توانید یک `MailMergeDataSource` را در کد بسازید، مجموعه داده‌ها اضافه کنید و فیلدها را با `AddText` پر کنید. این روش زمانی مفید است که داده‌ها از پیش در برنامه شما موجود باشند.

### آیا ادغام نامه قالب داده را بر اساس پسوند فایل تشخیص می‌دهد؟

خیر. قالب داده بر اساس محتوا تشخیص داده می‌شود، بنابراین یک منبع دادهٔ پشتیبانی‌شده نیازی به پسوند خاصی ندارد.

### آیا می‌توانم داده‌ها را از یک جریان که جست‌وجو را پشتیبانی نمی‌کند بخوانم؟

بله. ادغام نامه از جریان‌های غیرقابل جست‌وجو پشتیبانی می‌کند.

### اگر منبع داده خالی باشد یا مجموعه داده‌ای نداشته باشد چه می‌شود؟

منبع داده باید حداقل یک مجموعه داده داشته باشد. پیش از شروع عملیات ادغام مطمئن شوید که حداقل یک رکورد وجود دارد.

### اگر منبع داده قالب نامعتبری داشته باشد چه می‌شود؟

اگر محتوا به‌عنوان یکی از قالب‌های دادهٔ پشتیبانی‌شده شناسایی نشود، `NotSupportedException` پرتاب می‌شود. اگر شناسایی شود اما قالب نادرست باشد، `InvalidDataException` پرتاب می‌شود. پیام استثنا شامل اطلاعاتی دربارهٔ مکان خطا است.

### آیا می‌توانم پس از بازگشت هندلر از ارائهٔ تولید شده استفاده کنم؟

ارائهٔ پاس‌داده‌شده به هندلر `MergeToMultiplePresentations` متعلق به ادغام نامه است و پس از بازگشت هندلر از بین می‌رود. آن را ذخیره کنید یا محتوای مورد نیاز را داخل هندلر کپی کنید و پس از بازگشت هندلر آن را نگه ندارید یا به‌صورت دستی نابود نکنید.

### آیا هندلر به‌صورت موازی فراخوانی می‌شود؟

خیر. ارائه‌های تولید شده به‌صورت متوالی، در نخ فراخوان پردازش می‌شوند. در هر زمان فقط یک ارائهٔ تولید شده در حافظه نگه داشته می‌شود.

### اگر استثنایی داخل هندلر رخ دهد چه می‌شود؟

عملیات ادغام متوقف می‌شود و استثنا به‌طور یکسان به فراخوان منتقل می‌شود. ارائه‌های قبلاً پردازش‌شده تحت تأثیر قرار نمی‌گیرند و مجموعه داده‌های باقی‌مانده پردازش نمی‌شوند.

### آیا می‌توانم از مقادیر فیلدها برای تولید نام فایل خروجی استفاده کنم؟

بله. هندلر مجموعه دادهٔ جاری را از طریق آرگومان‌های خود در اختیار می‌گذارد. می‌توانید از `GetText` برای دریافت فیلدها استفاده کنید و برای هر ارائهٔ تولید شده یک نام فایل بسازید. مطمئن شوید مقادیر برای نام‌گذاری فایل در محیط هدف معتبر هستند.
