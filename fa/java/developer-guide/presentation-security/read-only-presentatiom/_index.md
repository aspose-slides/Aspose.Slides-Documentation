## **مقدمه**

در PowerPoint 2019، مایکروسافت تنظیم **Always Open Read-Only** را به عنوان یکی از گزینه‌هایی که کاربران می‌توانند برای محافظت از ارائه‌های خود استفاده کنند، معرفی کرد. ممکن است بخواهید از این تنظیم فقط‑خواندنی برای محافظت از یک ارائه استفاده کنید وقتی که

- می‌خواهید از ویرایش‌های تصادفی جلوگیری کنید و محتویات ارائه خود را ایمن نگه دارید. 
- می‌خواهید به افراد اعلام کنید که ارائه‌ای که ارائه کرده‌اید، نسخه نهایی است. 

پس از انتخاب گزینه **Always Open Read-Only** برای یک ارائه، وقتی کاربران ارائه را باز می‌کنند، توصیه **Read-Only** را می‌بینند و ممکن است پیامی شبیه به این مشاهده کنند: *برای جلوگیری از تغییرات تصادفی، نویسنده این فایل را به حالت فقط‑خواندنی تنظیم کرده است.*

توصیه فقط‑خواندنی یک بازدارنده ساده اما مؤثر است که از ویرایش جلوگیری می‌کند زیرا کاربران باید کاری انجام دهند تا این توصیه را حذف کنند قبل از آنکه اجازه ویرایش ارائه را داشته باشند. اگر نمی‌خواهید کاربران تغییراتی در ارائه ایجاد کنند و می‌خواهید این موضوع را به شکل مودبی به آن‌ها اطلاع دهید، توصیه فقط‑خواندنی گزینه خوبی برای شماست. 

> اگر یک ارائه با محافظت **Read-Only** در یک نسخه قدیمی‌تر از Microsoft PowerPoint باز شود—که از این عملکرد جدید پشتیبانی نمی‌کند—توصیه **Read-Only** نادیده گرفته می‌شود (ارائه به‌صورت معمولی باز می‌شود).

## **اعمال حالت فقط‑خواندنی**

Aspose.Slides for Java به شما اجازه می‌دهد یک ارائه را به حالت **Read-Only** تنظیم کنید، به این معنی که کاربران (پس از باز کردن ارائه) توصیه **Read-Only** را می‌بینند. این کد نمونه نشان می‌دهد چگونه یک ارائه را در جاوا با استفاده از Aspose.Slides به **Read-Only** تنظیم کنید:

```java
import com.aspose.slides.*;

Presentation pres = new Presentation();
try {
    pres.getProtectionManager().setReadOnlyRecommended(true);
    pres.save("ReadOnlyPresentation.pptx", SaveFormat.Pptx);
} finally {
    if (pres != null) pres.dispose();
}
```

{{% alert color="info" %}} 

**توجه**: توصیه **Read-Only** صرفاً برای جلوگیری از ویرایش یا متوقف کردن تغییرات تصادفی در یک ارائه PowerPoint است. اگر شخصی با انگیزه—که می‌داند چه کاری انجام می‌دهد—تصمیم بگیرد ارائه شما را ویرایش کند، می‌تواند به‌راحتی تنظیم فقط‑خواندنی را حذف کند. اگر به‌طور جدی نیاز دارید از ویرایش غیرمجاز جلوگیری کنید، بهتر است از [محافظت‌های سخت‌گیرانه‌تر که شامل رمزنگاری و گذرواژه می‌شوند](https://docs.aspose.com/slides/fa/java/password-protected-presentation/) استفاده کنید. 

{{% /alert %}} 

## **سؤالات متداول**

### چگونه 'Read-Only recommended' با حفاظت کامل با گذرواژه تفاوت دارد؟

'Read-Only recommended' فقط یک پیشنهاد برای باز کردن فایل در حالت فقط‑خواندنی نمایش می‌دهد و به‌راحتی می‌توان از آن عبور کرد. [حفاظت با گذرواژه](/slides/fa/java/password-protected-presentation/) در واقع باز کردن یا ویرایش را محدود می‌کند و زمانی مناسب است که به کنترل‌های امنیتی واقعی نیاز داشته باشید.

### آیا می‌توان 'Read-Only recommended' را با آب‌نشان‌ها ترکیب کرد تا ویرایش‌ها بیشتر discouraged شوند؟

بله. این توصیه می‌تواند با [آب‌نشان‌ها](/slides/fa/java/watermark/) به عنوان یک بازدارنده بصری ترکیب شود؛ آن‌ها مکانیزم‌های جداگانه‌ای هستند و با هم به‌خوبی کار می‌کنند.

### آیا یک ماکرو یا ابزار خارجی همچنان می‌تواند فایل را وقتی توصیه فعال است، تغییر دهد؟

بله. این توصیه مانع تغییرات برنامه‌نویسی نمی‌شود. برای جلوگیری از ویرایش‌های خودکار، از [گذرواژه‌ها و رمزنگاری](/slides/fa/java/password-protected-presentation/) استفاده کنید.

### 'Read-Only recommended' چگونه با متدهای 'isEncrypted' و 'isWriteProtected' مرتبط است؟

آن‌ها سیگنال‌های متفاوتی هستند. 'Read-Only recommended' یک اعلان نرم و اختیاری است؛ [isWriteProtected](https://reference.aspose.com/slides/fa/java/com.aspose.slides/protectionmanager/#isWriteProtected--) و [isEncrypted](https://reference.aspose.com/slides/fa/java/com.aspose.slides/protectionmanager/#isEncrypted--) محدودیت‌های واقعی نوشتن یا خواندن را نشان می‌دهند که به گذرواژه یا رمزنگاری وابسته‌اند.
