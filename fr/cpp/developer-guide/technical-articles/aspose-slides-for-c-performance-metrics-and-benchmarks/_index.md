## **Objectif**
Les performances sont souvent le premier facteur critique lors du choix d'un composant. Cet article mesure les performances d'Aspose.Slides pour C++ et VSTO 2008. Les tests simples sont réalisés sur des systèmes d'exploitation, des composants matériels et des configurations similaires. 

Cet article présente les mesures de performances pour les produits incluant **Aspose.Slides for C++** et **VSTO 2008**. Les estimations de performances présentées ici visent à vous aider à comprendre ce à quoi vous attendre de différents composants dans certains scénarios couramment utilisés sous des configurations similaires sur du matériel de base fonctionnant sous des systèmes d'exploitation largement répandus. Naturellement, les performances de votre application dépendent de vos données, des schémas d'accès aux données, de la taille du cache, d'autres paramètres de configuration, du système d'exploitation et du matériel, etc. Le benchmark a pour objectif d'illustrer comment les composants fonctionnent sous des conditions matérielles minimales ; plus le matériel est rapide, plus les tâches seront traitées rapidement par les composants.

Les benchmarks fournissent des directives et aident à définir des attentes opérationnelles de base. Le sujet présente les tests de benchmark qui ont été effectués sur Aspose.Slides for C++ et VSTO 2008. Les mesures de performance *{*} permettent même aux utilisateurs novices d'évaluer les performances du composant qu'ils utilisent. Les tests *{*} vous permettront de benchmarker objectivement un composant à l'aide d'une variété de tests de vitesse différents. Toutes les tâches sont courantes et soigneusement choisies, explorant les fonctionnalités pertinentes afin de s'assurer que les deux composants puissent accomplir les tâches facilement. De plus, les API utilisées pour réaliser un test par chaque composant sont soigneusement sélectionnées afin d'obtenir les meilleurs résultats possibles qu'un composant peut produire lors de l'évaluation de ses performances, et toutes les tâches ont été implémentées deux ou trois fois pour mieux juger les chiffres.

## **Méthodologie de test**
Tous les tests de performance ont été réalisés sur des combinaisons communes de matériel et de système d'exploitation, sans configuration personnalisée, réglage ou autre technique d'amélioration des performances. Tous les tests ont été exécutés avec les installations des composants sur le même système, qui était autrement inactif. Pour obtenir des mesures précises, nous avons exécuté toutes les tâches deux ou trois fois afin d'évaluer au mieux un composant et d'obtenir des lectures précises.
