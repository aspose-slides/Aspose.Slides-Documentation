## **소개**

Aspose 구성 요소가 자동화보다 더 나은 대안이 되는 이유는 여러 가지가 있습니다. 주요 이유는 다음과 같습니다:

- 보안
- 안정성
- 확장성/속도
- 가격
- 기능

아래는 각 핵심 포인트에 대한 자세한 설명입니다.

## **중요한 질문**
- 왜 Aspose 구성 요소가 Microsoft Office 자동화보다 훨씬 더 좋은 선택인가요?

Aspose에서 가장 많이 듣는 두 가지 질문은 다음과 같습니다 :

- 제품을 실행하려면 Microsoft Office가 설치되어 있어야 합니까?

간단한 답은 **아니오** 입니다. Aspose와 Aspose 구성 요소는 완전히 독립적이며 Microsoft Corporation과 제휴, 승인, 후원, 혹은 기타 어떤 형태로도 연관되지 않습니다.

- Microsoft Office 자동화를 사용하는 대신 Aspose 제품을 사용해야 하는 이유는 무엇입니까?

가장 짧게 말씀드리면, *Microsoft 자체가 소프트웨어 솔루션의 Office 자동화를 강력히 권장하지 않는다는 점*이 가장 큰 이유입니다: [Microsoft Article](https://support.microsoft.com/en-us/kb/257757)

## **보안**
위에서 인용한 Microsoft Article의 직접 인용문은 다음과 같습니다 :

*"Office Applications는 서버 측에서 사용하도록 설계되지 않았으며, 따라서 분산 구성 요소가 직면하는 보안 문제를 고려하지 않습니다. Office는 들어오는 요청을 인증하지 않으며, 매크로를 무심코 실행하거나 매크로를 실행할 수 있는 다른 서버를 시작하는 것을 방지하지 못합니다. 익명 웹에서 서버로 업로드된 파일을 열지 마세요! 마지막으로 설정된 보안 설정에 따라 서버는 관리자 또는 시스템 컨텍스트에서 매크로를 실행하여 전체 권한을 획득하고 네트워크를 손상시킬 수 있습니다! 또한 Office는 Simple MAPI, WinInet, MSDAIPP와 같은 많은 클라이언트 측 구성 요소를 사용하여 처리 속도를 높이기 위해 클라이언트 인증 정보를 캐시할 수 있습니다. Office가 서버 측에서 자동화될 경우, 하나의 인스턴스가 여러 클라이언트를 서비스할 수 있으며, 해당 세션에 인증 정보가 캐시되어 있으면 한 클라이언트가 다른 클라이언트의 캐시된 자격 증명을 사용해 부여되지 않은 접근 권한을 얻을 수 있습니다."*

Aspose 제품은 매우 안전합니다. 따라서 Aspose 구성 요소는 중요한 시스템 리소스에 잠재적인 위험을 초래하지 않습니다. 또한 Aspose 구성 요소가 문서를 열 때 매크로가 자동으로 실행되지 않습니다. Aspose 구성 요소는 개발자가 Office 파일을 만들고, 조작하고, 저장할 수 있도록 설계되었습니다. Microsoft Office 패키지와 관련된 위험은 Aspose 구성 요소에 내재되어 있지 않습니다.

## **안정성**
위에서 인용한 Microsoft Article의 직접 인용문은 다음과 같습니다 :

*"Office 2000, Office XP 및 Office 2003은 Microsoft Windows Installer(MSI) 기술을 사용하여 최종 사용자의 설치 및 자동 복구를 더 쉽게 합니다. MSI는 "첫 사용 시 설치" 개념을 도입하여 기능을 런타임에 동적으로 설치하거나 구성할 수 있게 합니다(시스템 또는 주로 특정 사용자 기준). 서버 측 환경에서는 이로 인해 성능이 저하되고 사용자에게 설치를 승인하거나 적절한 설치 디스크를 제공하라는 대화 상자가 나타날 가능성이 높아집니다. Office는 최종 사용자 제품으로서 회복성을 높이기 위해 설계되었지만, 서버 측 환경에서는 MSI 기능 구현이 역효과를 냅니다. 또한 Office는 서버 측에서 실행될 경우 설계·테스트되지 않아 전반적인 안정성을 보장할 수 없습니다. 네트워크 서버에서 Office를 서비스 구성 요소로 사용하면 해당 서버 및 전체 네트워크의 안정성이 저하될 수 있습니다. 서버 측에서 Office를 자동화하려는 경우, 핵심 기능에 영향을 주지 못하고 필요 시 재시작이 가능한 전용 컴퓨터에 프로그램을 격리하는 것이 좋습니다."*

Aspose 구성 요소는 단일 DLL로 패키징되므로 추가적인 부품이나 조각을 설치할 필요가 전혀 없습니다. Aspose 구성 요소는 C++ 애플리케이션에서만 사용되며, 인간의 응답을 기다리도록 설계된 코드가 포함되어 있지 않습니다. Aspose 구성 요소는 철저히 테스트되었으며 매우 안정적입니다. Aspose 구성 요소는 **IBM**, **Hilton**, **Reader's Digest**, **Bank of America** 등과 같은 [기업](https://about.aspose.com/customers)에서 사용되고 있습니다.

## **확장성/속도**
위에서 인용한 Microsoft Article의 직접 인용문은 다음과 같습니다 :

*"서버 측 구성 요소는 최소한의 오버헤드와 높은 처리량을 제공하는 재진입 가능하고 다중 스레드 COM 구성 요소여야 합니다. Office Applications는 거의 모든 면에서 정확히 반대입니다. 재진입이 불가능하고 STA 기반 자동화 서버이며, 단일 클라이언트를 위한 다양한 하지만 리소스를 많이 소모하는 기능을 제공합니다. 서버 측 솔루션으로서 확장성이 거의 없으며, 메모리와 같은 중요한 요소에 고정된 제한이 있어 구성으로 변경할 수 없습니다. 더 중요한 점은 전역 리소스(메모리 매핑 파일, 전역 추가 기능 또는 템플릿, 공유 자동화 서버 등)를 사용하여 동시에 실행 가능한 인스턴스 수가 제한되고, 다중 클라이언트 환경에서 구성될 경우 경쟁 조건이 발생할 수 있다는 것입니다. 여러 Office Application 인스턴스를 동시에 실행하려는 개발자는 풀링이나 직렬화 접근을 고려하여 잠재적인 교착 상태나 데이터 손상을 방지해야 합니다."*

Aspose 구성 요소는 높은 확장성을 제공하며 매우 빠릅니다. Office Application은 수백, 수천 명의 사용자가 동시에 사용하도록 설계되지 않았지만, Aspose 구성 요소는 바로 그 목적을 위해 설계되었습니다. 우리의 구성 요소는 순수 C++ 솔루션이며, 단일 서버에서 단일 애플리케이션을 구동하든, 로드 밸런싱된 웹 폼을 통해 엔터프라이즈 규모 애플리케이션을 구동하든 문제없이 작동합니다.

## **가격**
Microsoft Office 자동화를 사용하는 경우, 해당 애플리케이션을 실행하는 각 머신에 Microsoft Office 라이선스를 구매해야 합니다. 애플리케이션이 Office 파일을 생성하거나 조작해야 하지만 사용자가 Microsoft Office를 보유할 필요가 없는 경우도 많습니다. Aspose는 무제한 사용자에게 배포할 수 있는 매우 **비용 효율적**이고 로열티 무료 재배포 라이선스를 제공하므로 라이선스 고민이 없습니다. 웹 기반 애플리케이션을 만들 때 Microsoft Office 자동화 구성 요소는 서버 측 솔루션에 대한 가격이나 라이선스가 제공되지 않으며, 따라서 Microsoft Office 구성 요소를 이용한 웹 애플리케이션 배포를 위한 적절한 라이선스 솔루션이 없습니다. Aspose는 서버 기반 애플리케이션을 위한 매우 **비용 효율적**인 솔루션을 제공합니다.

## **기능**
Aspose 구성 요소는 Office 파일 관리에 필요한 모든 기능과 그 이상을 제공합니다. 개발자가 최소한의 작업으로 최고의 결과를 얻을 수 있도록 설계되었습니다. Office 자동화와 달리, Aspose 구성 요소는 강력하고 시간 절약 기능을 많이 제공합니다. 예를 들어, [Aspose.Cells](https://products.aspose.com/cells/cpp/)은 개발자가 **DataTable** 또는 **DataView**에서 데이터를 직접 Excel 파일로 가져올 수 있는 기능을 제공합니다. [Aspose.Words](https://products.aspose.com/words/net/)는 개발자가 C++ 데이터 객체에서 직접 Word(메일 병합) 문서를 채울 수 있는 유사한 기능을 제공합니다. [Aspose 제품군 전체](https://products.aspose.com/total/cpp/)는 각각 고유하고 강력한 기능을 보유하고 있습니다. Aspose 구성 요소를 구매하면 개발 팀에 접근할 수 있다는 큰 장점이 있습니다. 우리 개발 팀은 귀사의 필요 기능이 다른 기업에도 필요할 가능성이 높다고 판단합니다. 모든 기능 요청을 반영할 수는 없지만, 팀은 지원을 제공할 때 매우 개방적이고 유연하게 대응합니다. 이러한 사고 방식이 Aspose 구성 요소를 강력하게 만든 원동력입니다. Office 자동화 객체에서 추가 기능이 필요할 경우, 해당 기능이 추가될 가능성은 매우 낮습니다.
