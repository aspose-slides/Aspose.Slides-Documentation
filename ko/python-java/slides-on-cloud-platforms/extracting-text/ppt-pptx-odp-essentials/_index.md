## **소개**

프레젠테이션 텍스트를 추출하면 슬라이드 콘텐츠를 검색, 분석, 접근성 및 현지화에 활용할 수 있습니다. Python 애플리케이션에서는 추출된 텍스트를 인덱스, 문서 관리 시스템 또는 언어 처리 파이프라인에 공급할 수 있습니다. 클라우드 워커는 업로드 또는 객체 스토리지에서 받은 파일에 동일한 워크플로를 적용할 수 있습니다.

이 문서에서는 PPT, PPTX, ODP가 텍스트를 저장하는 방식과 이러한 차이가 추출에 어떻게 영향을 미치는지 설명합니다. Aspose.Slides for Python via Java는 세 형식 모두 로드를 지원합니다; 자세한 내용은 [지원되는 파일 형식](/slides/ko/python-java/supported-file-formats/)을 참조하세요.

## **텍스트 추출의 실용적인 활용**

- **문서 워크플로:** 프레젠테이션 콘텐츠를 문서 관리 시스템에 가져오고 원본 파일 메타데이터와 연결합니다.
- **검색 인덱싱:** 슬라이드 텍스트를 인덱싱하면서 프레젠테이션 이름 및 슬라이드 번호를 각 결과에 보존합니다.
- **콘텐츠 분석:** 프레젠테이션 아카이브 전체에서 주제, 용어 및 반복되는 테마를 식별합니다.
- **접근성 및 현지화:** 보조 도구나 번역 워크플로에 텍스트를 제공하며, 읽기 순서와 컨텍스트를 추가로 검토합니다.
- **레이아웃 분석:** 슬라이드 구조를 확인하거나 구조화된 내보내기를 준비할 때 텍스트와 객체 위치를 결합합니다.

## **프레젠테이션 형식 개요**

### **PPT: 레거시 PowerPoint 형식**

PPT는 PowerPoint 97–2003과 연관된 바이너리 형식입니다. 해당 레코드는 XML 문서처럼 처리할 수 없습니다. 파서는 슬라이드 콘텐츠를 재구성하기 위해 바이너리 구조와 그 관계를 이해해야 합니다.

텍스트는 슬라이드 객체, 노트 및 코멘트에 존재할 수 있습니다. 추출 워크플로는 프레젠테이션을 하나의 연속 텍스트 스트림으로 다루기보다, 포함할 소스를 정의해야 합니다.

### **PPTX: Office Open XML**

PPTX는 XML 파트와 기타 리소스를 포함하는 ZIP 패키지입니다. 슬라이드 텍스트는 일반적으로 `ppt/slides/ko/slideX.xml`의 `a:t` 요소에 나타납니다. 노트는 별도의 notes-slide 파트에 저장되며, 코멘트는 패키지 관계를 통해 연결된 자체 파트를 가집니다.

슬라이드 XML에서 텍스트 요소만 읽으면 패키지 내 다른 위치에 저장된 콘텐츠를 놓칠 수 있습니다. 또한 서식이나 읽기 순서를 재구성하지 않습니다. 완전한 워크플로는 레이아웃, 그룹형 쉐이프, 표, 차트 및 관련 파트를 고려해야 할 수 있습니다.

### **ODP: OpenDocument 프레젠테이션**

ODP는 LibreOffice Impress와 같은 애플리케이션에서 사용하는 패키징된 OpenDocument 프레젠테이션 형식입니다. PPTX와 마찬가지로 ZIP 패키지 내부에 XML을 포함하지만, OpenDocument 용어와 구조를 사용합니다.

프레젠테이션 콘텐츠는 주로 `content.xml`에 저장됩니다. 단락 텍스트는 `text:p`와 같은 요소를 사용하고, 스팬 및 기타 텍스트 기능을 위해 중첩 요소를 사용합니다. 따라서 PPTX 전용 XML 쿼리를 ODP에 직접 재사용할 수 없습니다.

## **Python에서 공통 프레젠테이션 모델 활용**

[Presentation](https://reference.aspose.com/slides/ko/python-java/aspose.slides/presentation/) 클래스는 지원되는 프레젠테이션 파일을 로드하여 애플리케이션 코드가 각 형식별로 별도의 패키지나 바이너리 파서를 구현하지 않고도 슬라이드와 그 객체를 다룰 수 있게 합니다.

추출을 클라우드 워커에 통합하기 전에 [설치](/slides/ko/python-java/installation/)를 따라야 합니다. 배포 및 JVM 수명 주기와 관련된 사항은 [클라우드 플랫폼의 Slides](/slides/ko/python-java/slides-on-cloud-platforms/)를 참조하세요.

추출 설계에서 다음 결정을 명확히 유지하십시오:

- **콘텐츠 범위:** 슬라이드 텍스트, 노트, 코멘트, 표 및 차트 레이블을 어떻게 처리할지 결정합니다.
- **읽기 순서:** 슬라이드 경계를 유지하고 객체 순서가 충분하지 않을 경우 레이아웃 정보를 사용합니다.
- **이미지 내 텍스트:** 스크린샷이나 스캔된 슬라이드에 텍스트가 포함된 경우 별도의 OCR 워크플로를 사용합니다.
- **출력 구조:** 소스 식별자를 유지하고 UTF-8과 같이 필요한 언어를 지원하는 인코딩으로 텍스트를 작성합니다.

## **결론**

PPT는 바이너리 형식 처리가 필요하고, PPTX와 ODP는 서로 다른 XML 패키지 구조를 사용합니다. 프레젠테이션 라이브러리는 Python에서 이러한 형식을 다루기 위한 공통 출발점을 제공합니다. 콘텐츠 범위와 읽기 순서를 정의하면 결과 텍스트를 인덱싱, 분석 및 현지화에 유용하게 만들 수 있습니다.

## **FAQ**

**파일을 압축 해제해서 PPT 텍스트를 추출할 수 있나요?**

아니요. PPT는 바이너리 구조를 사용합니다. ZIP과 XML 방식은 PPTX 및 ODP와 같은 패키징된 형식에 적용됩니다.

**PPTX에서 노트와 코멘트가 메인 슬라이드 텍스트와 함께 저장되나요?**

이들은 별도의 패키지 파트를 사용합니다. 슬라이드 XML만 읽어서는 자동으로 포함되지 않습니다.

**일반 텍스트 추출이 스크린샷 안의 텍스트를 포착하나요?**

아니요. 스크린샷 텍스트는 편집 가능한 슬라이드 텍스트가 아니라 이미지의 일부입니다. OCR이 필요합니다.
